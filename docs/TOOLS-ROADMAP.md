# 工具矩阵执行计划（求职工作台战略落地）

> 2026-09-28 制定。来源：用户「四件事 + 三层工具矩阵」规划（承接搜索流量 / 建立信任 / 沉淀结构化数据 / 形成转化路径），
> 对照仓库实测现状修正后形成的执行版。本文档是工具线的唯一路线图，后续批次按此推进，勿另起炉灶。

## 1. 战略定位

站点最终形态不是题库网站，是**面向 AI Agent 岗的求职工作台**：

```
搜到 JD 拆解页 → 保存目标岗位 → Gap 自测 → 发现短板 → 题库补课
→ 项目匹配器选项目 → 简历优化器改写 → 模拟面试训练 → 题库/面经回流
```

工具分三层：

| 层 | 工具 | 作用 |
| --- | --- | --- |
| 引流 | JD 拆解样板页（/jd）、术语库、题库、路线 | 承接搜索流量，静态页负责收录 |
| 诊断 | JD 分析器、简历体检、Gap 自测、项目匹配器 | 给出可感知的个人化帮助 |
| 成交 | 模拟面试、复盘本、投递 CRM、训练营入口 | 深度陪跑转化 |

原则：**静态样板页负责收录，交互工具负责个性化**。每个静态页底部放工具入口，每个工具结果页推荐相关静态页。

## 4. 技术架构决策（已定，勿反复）

- **纯前端规则引擎**：所有交互工具与 /tools/resume 同形态——零后端、零上传、文本不出浏览器。LLM 增强层（用户自填 key）留给 v2，接口设计见 `_resume_optimizer/research.md` §8.3。
- **JD 样板页 = content/jd/*.md**：frontmatter 字段 `slug/company/title/role/family/level/summary/cats/qaSlugs/keywords/updated`，正文固定 10 节 `## ` 标题。cats 用 content/interview/categories.json 词表，qaSlugs 必须真实存在于 content/qa。
- **JD 口径红线**：样板页是「该方向公开 JD 的高频归纳，非某一篇特定 JD」，页面明示；不写具体薪资/团队/编制数字；业务推测用「大概率/可能」并标置信度。与 lib/companies 的 company 字段口径一致。
- **页面风格**：内容页（/jd）用面试间 `.ivu-` 暖纸底体系；工具页用白底 `.rt-` 体系扩展。CSS 前缀隔离，不动 globals.css。
- **互链规则**：JD 页 → 题库（cats 自动）+ 简历体检 + Gap 自测 + 项目匹配器 + 同公司聚合页；工具结果页 → 相关 JD 样板页 + 题库。
- **数据回流**：本批不做账号体系（登录/保存/CRM 等到账号决策后再上），先把「可分享的诊断结果」做出来。

## 6. 合规与信任红线（工具线通用，永久生效）

1. 不伪造经历：系统输出区分「用户事实」与「表达建议」，指标位置留空让用户填真实值。
2. 默认脱敏：工具页明示「文本不出浏览器」；未来上传功能必须先做脱敏提示。
3. 不用「保过/真题/内部渠道」宣传：一律写「公开面经/公开 JD 的高频归纳」。
4. AI 声明：推断类内容（业务推测、隐藏要求）标注置信度，页面标「AI 辅助归纳，需人工核验」。
5. 论文/数据引用红线沿用站内全局规范（先核实再写，记不清不写）。
