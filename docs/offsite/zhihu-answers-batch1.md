## 底稿 1 · 回答「面试 AI Agent 岗位时，哪些问题能快速区分新手和高手？」

问题 URL：https://www.zhihu.com/question/2049047173677987500

区分新手和高手，不需要问偏题怪题，就看下面这五道。它们都有新手能开口、高手能分层的地方。

**1. Agent 的记忆系统怎么设计？**

新手的答法是「存到向量库里」。高手会分层讲：上下文窗口是工作记忆，管本轮任务；向量库存跨会话的情景和语义记忆；数据库放需要精确读写的结构化事实。每层还要说清三件事：什么值得记、怎么检索回来、什么时候过期。

**2. Agent 为什么会陷入死循环？怎么治理？**

新手会说「加个最大轮数」。高手会指出根子：模型看不到失败——错误输出被当成进展、两个工具互相踢皮球，轮数上限只是兜底。治理是检测加干预：轨迹指纹识别重复动作、进度指标判断有没有实质推进，检测到之后升级提示、换路线，或者交还人。

**3. 改了一版提示词，怎么确认没改坏别的地方？**

新手靠感觉。高手靠回归评测集：改前改后跑同一批用例，对比任务成功率、轨迹质量、成本三类指标，绿了才上线，再配线上灰度兜底。没有回归评测的 Agent 迭代等于盲飞。

**4. 多 Agent 跑一轮任务，Token 都花在哪？**

这题考的是算账能力。用户输入只是一小部分：系统提示和工具定义每轮都发，对话历史和工具结果逐轮全量重发，多个 Agent 各带各的上下文，循环一长，一句话能烧掉几十 M Token。控制手段是前缀瘦身、历史裁剪压缩、工具结果即用即弃、模型分级路由。

**5. 同一个模型，换个框架效果差很多，为什么？**

高手会提到 harness：循环控制、上下文管理、工具执行、权限和日志这些模型外面的工程框架。模型只负责决定下一步，剩下的都是 harness 决定的，所以它直接决定效果上限。能把这层讲清楚的人，一般真的调过生产级 Agent。

## 底稿 2 · 回答「你目前主要靠什么方式来准备 AI Agent 面试？」

问题 URL：https://www.zhihu.com/question/2010307705408091202

我们社区里拿到 offer 的成员，准备路径基本是三步，供参考。

**第一步：按方向过一遍高频题，建立骨架。**

Agent 岗的考点集中在五块：Agent 工程（范式选择、记忆、工具调用、多智能体）、RAG（切分、检索、重排、评估）、大模型基础（Transformer、KV Cache、微调与对齐）、评测与安全、以及项目深挖。先把每块的高频题过一遍，知道考什么，比直接啃论文高效。

**第二步：用真题的追问链自测，暴露薄弱点。**

面试官的问法不会停在定义，比如问 RAG 不会只问「什么是 RAG」，会顺着问「无标题文档怎么切分」「千万级语料召回不准怎么排查」。每道题准备三层：30 秒版本的标准答案、面试官可能的追问、这道题的常见坑。自测的时候按这三层过，卡在哪层哪层就是薄弱点。

**第三步：模拟面试练表达。**

知道答案和面试时讲清楚是两回事。找朋友互相问，或者用模拟面试工具（我们站上有一个免费的，五种面试官人格，可以按岗位出剧本、按简历深挖），重点是练「先给结论再展开」的表达结构。

最后一个提醒：项目准备比八股更重要。面试官顺着简历项目往下挖三层，编的经历一定会露馅，所以宁可项目小一点，也要每个技术选型都能说出理由和踩过的坑。

## 底稿 3 · 回答「AI agent 开发工程师面试指南？」

问题 URL：https://www.zhihu.com/question/12443212118

按 2026 年大厂的实际考察情况，Agent 开发岗的面试内容可以分成四块，逐块说准备要点。

**一、Agent 工程能力（权重最大）**

必考：ReAct、Plan-and-Execute、Reflection 三种范式的区别和选型；记忆系统分层（工作记忆、长期记忆、结构化事实各放哪）；工具调用的并行与串行判断；多 Agent 的协作拓扑和上下文隔离。这部分的考察已经从「用过 LangChain 吗」进化到「死循环怎么治理」「Token 账单怎么控制」这类生产问题，准备的时候要往运维和成本方向多想一层。

**二、RAG 系统**

必考：完整流水线（切块、向量化、检索、重排、生成）每一环的坑；BM25 和向量检索怎么混用；RAG、微调、长上下文三条路线怎么选；检索质量怎么评。项目类的问法是「为什么选这个方案、遇到了什么问题、怎么解决的」，答不出细节的项目等于没写。

**三、大模型基础**

必考：Attention 和 KV Cache（为什么推理复杂度能从 O(n²) 降到 O(n)、显存为什么扛不住）、微调方法对比、对齐算法（PPO/DPO/GRPO）的直觉理解。 infra 岗位会追问到 PagedAttention 和推理框架层面。

**四、项目深挖**

项目准备的原则：宁可小而真，不要大而虚。一个有真实用户的小项目，比一个跑不通的大项目有说服力得多。每个项目准备三件事：技术选型的理由、遇到的最大的坑、如果重做会怎么改。
