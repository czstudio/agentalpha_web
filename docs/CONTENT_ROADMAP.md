## 1. 硬规则（每批都适用，违反即返工）

1. **写作一律 gemini-3.1-pro-preview 主笔 + oil-tone 规范**（用户 2026-09-28 指定）。任务书锁字数下限；gpt-5.6-sol 只做兜底。Claude 不写发布内容（横评编造前科），只做分析。
2. **事实红线**：搬运河飞书内容时，宝典各文档题数口径互相矛盾（如 RAG 章 80+ vs 565），**站内不出现精确宝典题数**，用量词；新写内容必须有事实底稿（`model_bakeoff/qa_gen/digests/` 模式）。
3. **不用占位页**：导读/真题集没写好之前，专栏目录保留飞书外链；写好一篇换一篇内链。
4. **每批验收门禁**：oil-tone lint 0 FAIL → `tsc --noEmit` + `next build` 双绿 → 图片引用 0 缺失 → push 后 `git ls-remote` 核对 → IndexNow 提交新 URL → 线上 curl 回读 200。
5. **中转站限频**：跑批 max_workers≤2，403 = 限频（等 3 分钟自愈），禁止并发轰炸。
6. 并行会话同仓工作：`git add` 只显式列本批文件。

## 4. 每批作业流程（SOP）

1. 读本文档 + `git pull --rebase origin master`。
2. 选题/选材 → 事实底稿（新题走搜索调研，搬运走飞书 `lark-cli docs +fetch` + 逐条核查）。
3. gemini 撰写（任务书 = 结构 + oil-tone 硬规则 + 事实红线 + 字数下限）→ 人工逐篇核查数字 → 后处理（frontmatter 行内 tags、标题无冒号、「」引号）。
4. oil-tone lint 0 FAIL → tsc/build → push（`git -c http.proxy= -c https.proxy=`，ls-remote 核对）→ IndexNow → 线上回读。
5. 更新本文档状态列 + 提交（含路线图变更）。
