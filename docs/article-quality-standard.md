# AgentAlpha 文章金标准 v1

## 目标

专题文章的完成标准不是“字数够长”，而是让读者像读一篇成熟的技术公众号长文：先得到结论，再沿着故事、概念、工程方案和面试表达逐层深入；关键处有图、有表、有代码，读完能复述、能实践、能继续学习。

本标准参考[目标文章](https://mp.weixin.qq.com/s/4ZRDvL_j-xDP0liOVzJcjA)的阅读节奏与信息密度，只借鉴结构方法，不复制原文、案例、插图或措辞。所有 AgentAlpha 文章必须使用自己的例子、判断和来源。

## 文章分级

| 类型 | 适用场景 | 完成要求 |
| --- | --- | --- |
| 快讯/短笔记 | 版本变化、单个概念、活动通知 | 解决一个问题，给出结论、来源和下一步；不强行套用长文结构 |
| 实战文章 | 一个技术问题或项目拆解 | 结论先行，至少 4 个内容段，含一个可运行示例或流程图 |
| 专题长文 | 面试题、核心概念、完整项目、方法论 | 必须达到下方“金标准”，通过内容、视觉和事实三道验收 |

## 专题长文的固定骨架

1. **标题与承诺**：标题具体、有问题感；副标题说明读者读完能获得什么。
2. **真实场景开场**：用面试问答、线上故障、项目决策或生活类比切入，先让读者看到问题，而不是先堆定义。
3. **简要回答**：用 80–150 字给出可直接复述的答案，明确边界和核心关键词。
4. **详细解析**：6–8 个递进章节。每章至少包含“问题 → 通俗解释 → 技术机制 → 工程做法 → 常见坑/取舍”中的 3 项，不能只写百科定义。
5. **可验证材料**：至少一段代码、配置或伪代码；至少一张结构/时序/数据流图；至少一张对比表。主题不适合代码时，改为完整操作步骤或决策清单。
6. **面试迁移**：给出 30 秒回答、2 分钟展开、追问与反问，以及容易被扣分的说法。
7. **总结与行动**：用 3–7 条要点复盘，给出读者下一步可以执行的练习或检查项。
8. **相关内容**：推荐 3–5 篇站内文章、项目或题目，形成学习路径，而不是孤立的一篇文章。

## 文字与语言风格

- 先说人话，再补术语；每个新概念第一次出现时都要给出一句白话解释。
- 保留技术准确性，但用对话、类比、反例和小场景降低阅读门槛。
- 段落短、层级清楚；一个段落只承担一个动作或判断，避免连续大段说明。
- 结论、取舍、失败原因必须明确，少用“可以考虑”“视情况而定”这类无结论表达。
- 数据、论文结论、产品能力和版本行为必须有来源或注明验证日期；不得编造 benchmark、用户量和“业内都这样”。
- 可以有轻松的标题、问答和口语化转折，但不能用夸张标题替代事实，也不能模仿其他作者的独特句式。

## 图片、图表与排版

- 专题长文通常配置 8–18 个有信息作用的视觉元素；复杂主题可增加，简单主题按信息量减少，不为凑数放装饰图。
- 视觉元素优先顺序：架构图/流程图/时序图、关键代码解释图、概念对比图、真实界面或项目截图、章节转场插图。
- 每张图都要能回答“它解释了哪句话”；图片下方写简短图注，`alt` 写清主体和关系，不能只写“配图”。
- 代码块使用等宽字体、语法高亮和复制按钮；长代码拆成“核心片段 + 逐行解释”，不要把完整仓库贴进正文。
- 表格只保留能帮助决策的列；移动端优先，避免宽表横向滚动后仍无法阅读。
- 标题、引文、代码、图片和表格之间留出稳定间距；正文控制行宽和字号，禁止靠放大字体制造“丰富度”。
- 外部图片记录来源、许可证或授权状态；无法确认权利的素材改用自制图、项目截图或许可清晰的素材。

## 发布前验收清单

### 内容

- [ ] 一屏内能看到文章要解决的问题和简要答案。
- [ ] 章节形成递进关系，而不是同义标题拼接。
- [ ] 每个关键结论都有例子、机制或来源支撑。
- [ ] 有工程实现、失败案例或取舍，读者可以照着做。
- [ ] 有面试表达、追问和总结清单（非面试主题则换成实践检查清单）。
- [ ] 关联内容能继续带读者学习。

### 视觉与排版

- [ ] 图片、图表和截图承担解释职责，数量与内容复杂度匹配。
- [ ] 图片有图注和可访问的 `alt`，代码和表格在移动端可读。
- [ ] 文章首屏、章节标题、引用、代码、图片和结尾 CTA 的节奏经过预览检查。

### 事实与版权

- [ ] 外链、论文、版本号和截图来源可追溯，并记录更新日期。
- [ ] 未复制参考文章的正文、独有比喻、配图或标题句式。
- [ ] 草稿、审核、发布状态清楚；未完成金标准的专题只能标为草稿或施工中。

## 内容流水线

公众号/飞书原始资料 → 去重与事实核对 → 按本标准补齐故事、工程例子和视觉 → 编辑审校 → 移动端预览与链接检查 → 发布。

原始资料是素材，不是成稿。缺少出处、图片权利或关键工程细节时，先进入补料清单，不用“看起来完整”的占位内容发布。
