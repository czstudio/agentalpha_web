# AgentAlpha `/community` 独立视觉 QA

审查日期：2026-08-10  
审查范围：桌面端 1440×1000、移动端 390×844，补充键盘焦点、减弱动效和菜单打开态  
审查方式：只检查实际渲染页面，不读取或修改页面实现代码

## 结论

页面已经形成鲜明的深海军蓝、亮蓝和荧光绿编辑风格，首屏有辨识度，主内容对比度高，桌面端也有成熟的章节导览结构。当前最大问题不是“没有设计”，而是设计成果被两个问题拖累：**移动菜单几乎不可读**，以及**全页证据量过大、缺少分级与收纳**。

一句话印象：**硬核，但过载。**

- 综合视觉评分：**C+**
- 品牌辨识度：**A-**
- 层级与内容节奏：**C**
- 字体与可读性：**B-**
- 配色：**B**（移动菜单状态单独为 F）
- 布局与响应式：**C+ / C**
- 交互状态：**D+**
- 动效与无障碍基础：**B**
- “AI 模板感”：**A-**，页面具有明确的编辑设计语言，不像通用生成式模板

页面基础数据也说明了负担：桌面端约 31,588px 高，移动端约 32,734px 高；包含 52 个 section、58 个 figure、60 张图片和 6 张表格。移动端只完成了“纵向重排”，没有完成“信息减量与优先级重构”。

## 首屏与整体观感

首屏注意力顺序清楚：大标题、蓝色强调行、行动按钮。深色背景和巨型宋体标题形成了可信的“技术社区宣言”气质。桌面后续章节利用左侧导览、颜色分区和大标题维持了视觉识别。

但进入正文后，同一层级连续出现大量长文、截图、聊天记录、纸张型材料和表格，视觉叙事逐渐变成“证据堆放”。用户很难判断哪些是核心成果、哪些只是补充证明。移动端尤其明显：多个接近整屏高的图片卡片连续出现，CTA 到达成本过高。

## 配色验收标准

当前主色表现：

- `#F2F0E8` / `#101724`：约 15.73:1，通过。
- `#A8AFBA` / `#101724`：约 8.12:1，通过。
- `#7190FF` / `#101724`：约 6.10:1，通过。
- 白色 / `#7190FF`：约 2.94:1，不通过普通文字，且略低于 3:1。
- `#101724` / `#C9FF3D`：约 15.26:1，通过。

验收要求：

- 普通文字对比度 `>= 4.5:1`；24px 常规或 18.66px 粗体以上的大字 `>= 3:1`。
- 图标、按钮边框、输入边界和焦点可视状态与相邻颜色 `>= 3:1`。
- 亮蓝 `#7190FF` 上默认使用 `#101724` 文字；若必须白字，背景蓝需加深到白字 `>= 4.5:1`。
- 移动菜单浅色面板必须使用深色文字；不允许白字落在米白或透明浅色层上。
- 荧光绿只用于焦点、关键状态和小面积强调，避免成为长段正文背景。
- 任意遮罩打开时，底层内容亮度应明显降低，遮罩视觉不透明度建议 60% 以上。

## 字体验收标准

- 内容字体不超过 2 个家族：宋体负责展示标题，Avenir Next / PingFang SC 系负责正文；代码或数据允许额外使用等宽字体。
- 桌面 H1：72–104px；移动 H1：44–56px。当前约 100.8px / 54.6px，可保留。
- 桌面 H2：48–56px；移动 H2：34–40px。当前移动约 44.85px，应降低。
- 桌面 H3：28–32px；移动 H3：24–28px。
- 正文：桌面 17–19px，移动 16–18px；中文长文行高 1.6–1.8。当前常见正文行高约 1.92，可略收紧以缩短视觉长度。
- 正文单行最大宽度约 640–760px，或 32–38 个中文字符；不让长文横跨整个主栏。
- 辅助标签不小于 13px；承载关键信息时不小于 14px。
- 标题语义必须连续，页面只保留一个 H1；不得从 H3 直接跳到 H5。
- 字体加载完成前后不得出现明显跳版；字重与字宽需有匹配的 fallback。

## 图片与媒体比例验收标准

当前图片普遍使用 `object-fit: contain`，未发现明显像素拉伸；主要问题是不同素材共用近似容器后产生过大空边，导致图片中文字缩得过小。

建立四类媒体组件：

1. 产品和网页截图
   - 容器优先 16:9 或 3:2。
   - 使用 `contain`，不裁掉界面文字；容器使用统一深色或中性底垫。
   - 桌面主图最大高度约 560px；手机宽度 100%，高度按比例。

2. 报告、证书、海报、纸张材料
   - 保留原始比例，A4 类按 `1:√2` 处理。
   - 桌面单张显示宽 300–420px；手机单列。
   - 必须支持点击查看原图，缩略图内正文不作为唯一信息来源。

3. 聊天记录和竖屏证明
   - 使用原始竖向比例或 9:16 容器。
   - 桌面卡宽 320–360px；移动单列，默认展示高度建议不超过 480px，并提供展开/灯箱。
   - 同一段落最多并列或连续展示 3 张，其余收进图库。

4. 二维码
   - 独立 CTA 区展示，不裁切、不套强透视。
   - 桌面和移动有效边长至少 240–280 CSS px，四周保留安静区。

通用要求：

- 所有图片声明稳定的 `width/height` 或 `aspect-ratio`，避免累计布局偏移。
- 首屏必要图片优先加载，其余图片懒加载；提供合理的响应式资源尺寸。
- 图片中的关键文字必须在当前视口可读；若不可读，旁边需提供文字摘要和放大入口。
- 不以整页长图代替可访问的 HTML 文本。

## 布局验收标准

- 桌面内容最大宽度 1200–1280px；正文主栏 720–820px；章节侧栏 180–220px；左右安全边距至少 32px。
- 移动左右内边距 16px；章节垂直间距 56–72px，避免所有段落都用相同的大间距。
- 每个大章节遵循“结论 → 代表证据 → 查看全部”的固定结构。
- 同类卡片连续出现不得超过 3 个；不得连续超过 2 个视口高度而没有新的小标题、摘要或交互收纳点。
- 桌面侧栏吸附时不覆盖正文；当前章节状态要清楚但不能抢过主标题。
- 移动顶部导航与章节栏常驻高度合计 `<= 96px`；向下滚动可隐藏章节栏，向上滚动再显示。
- 章节导航当前项必须自动滚入可见区域；首项和末项都有完整内边距。
- 桌面表格在 768px 以下转换为键值卡片；若保留横向滚动，必须有明确滚动提示和可见边界。
- 页面底部 CTA 到达前，应提供中途加入入口或悬浮轻量入口，避免用户必须滚完 30k px。

## 动效与交互验收标准

已有优点：键盘焦点为约 3px 荧光绿实线，辨识度好；`prefers-reduced-motion: reduce` 下动画和过渡基本被压缩到近乎 0ms。

验收要求：

- 禁止 `transition: all`；只过渡 `transform`、`opacity`、`background-color`、`color` 等明确属性。
- hover/focus 反馈 160–220ms；菜单和抽屉 240–320ms；使用 ease-out，避免弹性过冲。
- 入场动画只使用透明度与轻微位移，位移不超过 16–24px；同屏级联总时长不超过 600ms。
- 导航进度条用 `transform: scaleX()`，不持续改动 width 触发布局。
- `prefers-reduced-motion` 下关闭自动滚动、视差、位移和级联，仅保留即时透明度变化，单次反馈不超过 1ms 或直接无动画。
- 打开移动菜单后：首个菜单项获得焦点；Tab 不逃出菜单；Escape 关闭；关闭后焦点返回菜单按钮。
- 菜单打开时锁定页面滚动，遮罩区域不可点击底层内容。
- 点击、键盘和触控反馈在 100ms 内出现；所有独立交互目标至少 44×44px。
- 焦点样式不得只依赖颜色，且不能被 sticky 容器或 overflow 裁掉。

## 响应式验收矩阵

至少在以下视口逐一验收：320×568、375×812、390×844、768×1024、1024×768、1440×1000。

每个视口都必须满足：

- `document.documentElement.scrollWidth <= window.innerWidth + 1`，无意外横向滚动。
- 文字、按钮、图片、表格和固定导航没有遮挡或重叠。
- 正文不小于 16px；关键辅助信息不小于 14px。
- 独立按钮、菜单项、图标按钮均至少 44×44px。
- 图片不变形、不裁掉产品界面关键文字，且可查看大图。
- 320px 宽时标题不溢出，英文长词和 URL 可换行。
- 768px 附近不出现“桌面侧栏已消失、移动章节栏尚未启用”的断层。
- 横屏手机和短视口中，菜单内容可滚动，关闭按钮始终可达。
- 页内锚点定位后，目标标题不被顶部 sticky 区遮住。
- 浏览器缩放 200% 后仍可完成菜单、导航和加入社区操作。

状态验收还应覆盖：默认、hover、focus-visible、active、菜单展开、页面滚动中、图片加载中/失败、慢网、减弱动效、200% 缩放。

## 建议修复顺序

1. 修复移动菜单的颜色、宽度、遮罩、滚动锁定和焦点闭环。
2. 把蓝底 CTA 的白字改为深海军蓝，并统一所有对比度不合格状态。
3. 将移动 H2 调至 34–40px，常驻导航总高压到 96px 内。
4. 每类证据只留 3 个代表项，其余折叠或进入灯箱/图库。
5. 拆分四种图片组件，统一比例、宽高、底垫和放大行为。
6. 将独立链接和导航热区统一到 44×44px，并去除 `transition: all`。

## 正向项

- 桌面与 390px 移动视口均未发现页面级横向溢出。
- 审查过程中未发现浏览器控制台错误。
- 深海军蓝正文区的主文字、辅助文字和荧光绿强调对比度充足。
- 首屏品牌感、章节分区和底部 CTA 都有明确视觉语言。
- 键盘焦点样式明显，减弱动效偏好已得到响应。
