AgentAlpha · 自进化控制台

自进化 Code Agent 框架

Agent 在处理 issue 时，可以通过四阶段轨迹级自进化保留经验。该过程包括多路 rollout、轨迹打分、策略变异与交叉、池化总结回注，以此提升 resolve rate。

01

场景故事

开源社区 3000+ issues 的自动修复流程，沉淀可复用经验

让 Agent 变强有两条路：换更强的模型，或者让它从自己的经验里学。这个项目走第二条：把 Agent 解题的轨迹（trajectory）当作可进化的对象——哪条轨迹解决了问题、用了哪些策略，抽象出来、打个分，好的策略变异、交叉、池化总结，再注入下一代 Agent 的提示里。

框架是四阶段循环：Original 阶段 N 路并行跑出基线轨迹；Alternative 阶段从高分轨迹生成替代策略再验证；Crossover 阶段把互补策略两两交叉产生新组合；Summary 阶段做全轨迹池化总结沉淀成策略库。防劣化靠加权无放回采样和 LLM rerank，成本靠每代 instance×rollout 预算和 API 调用核算控制。

进化效果在 SWE-bench 上度量：同预算下「纯多路采样」vs「进化迭代」的 resolve rate 对比——如果进化赢了，说明策略真的在积累，而不只是采样次数变多。

可迁移场景：包括客服话术策略优化、检索策略自动调优，以及任意可打分的 Agent 任务。

08

面试深挖预演

进化的「基因」是什么？和 AlphaEvolve 有什么区别？
AlphaEvolve/OpenEvolve 进化代码本身，使用 LLM 变异代码并用评估器打分。本项目进化解题策略，从轨迹里抽象出可迁移的策略描述，变异交叉的对象也是策略。代码进化适合有明确评估函数的任务，策略进化的适用面更广，在没有可执行评估器时也能运行。
crossover 交叉的是什么？怎么避免交叉出互相冲突的策略？
交叉过程使用互补的高分策略片段，例如分别擅长定位和测试构造的片段。冲突控制的方法是交叉前先做策略类型标注，包括定位、编辑、验证，只在互补类型间交叉。交叉后先进行小样本验证，然后再入池。
怎么证明提升来自进化而不是采样次数变多？
在同预算对照实验中，对照组把相同总数的 rollout 全部用在第 0 代的纯采样上，实验组则进行分代进化。两组的 resolve rate 对比结果代表了进化的净收益。
怎么防止进化劣化？
该机制分为三层。第一层是轨迹打分筛选，只让高分经验入池。第二层是加权无放回采样，使劣质策略权重衰减。第三层是逐代 baseline 对照，在劣化代回滚策略库。
成本怎么控？
每代预算等于 instance 数乘以每任务 rollout 数。框架内包含 API 调用核算脚本，用于统计单代成本。在实践中，先使用小 instance 集快速迭代策略库，然后再用大集合进行验证。
你的进化循环和强化学习是什么关系？
两者在结构上同构。多路 rollout、打分、选择、更新的过程等价于进化策略（ES）进行策略搜索。GRPO 的过程是组内采样、计算相对优势、更新参数。两者的区别在于更新载体（prompt 或策略库与模型参数的区别）以及样本利用率。我们的 LoRA 对照实验横跨了这两种方式，进化用于寻找方向，微调用于实现收敛。
防早熟收敛和字节 DAPO 有什么呼应？
同一个问题体现在两个层面。我们在 prompt 层使用策略多样性熵监控与强制变异，字节 DAPO 在参数层使用 Clip-Higher 非对称裁剪防止熵坍缩。这两种方法都用于保持探索能力，只是作用载体不同。
