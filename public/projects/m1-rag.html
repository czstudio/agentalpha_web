01

场景故事

从「能回答」到「可追责」：企业知识库的真实工程问题

金融独角兽的投研团队每天面对几百页研报、公告与政策文件——分析师问「某标的最新风险提示在第几页、原文怎么写」，传统做法翻文档半小时；RAG 一次检索直接给答案并附句级引用，内审可逐句跳回原文。

这个项目的知识底座是 2841 行的 RAG 全链（teaching/streamlit_rag2：teacher 完整答案 + student 实现骨架）：PDF 解析、递归分块、Chroma 向量库、检索、重排、引用问答一应俱全；金融侧配 1146 行的 ReAct Agent（六工具查股价/基本面/历史/股息/财务/多标的对比）和 2214 行的五角色研报产线（协调者→基本面/技术/风险分析师→撰写者），reports/ 里有真实生成的 AAPL 研报。

检索质量用 220 题 MS MARCO 黄金集实测：四级漏斗（BM25→向量→RRF 融合→按需再搜）Recall@10 从 0.900 提升到 0.991；分歧表逐题归因（向量救词面 21 题）。多 Agent 侧实测对抗注入 10/10 拒绝、15 项事实检查全对——金融场景的两条底线：不编数字、不做投资建议。

可迁移场景：换行业语料三步走、法务合同库（条款级切分）、医疗指南库（引用等级）

09

面试深挖预演

为什么定位金融场景？
金融是 RAG 最苛刻的场景：数字错一个就是事故，引用必须句句可回原文，合规要求不做投资建议。三道发布门（检索回归/引用覆盖/无据拒答）在金融不是加分项是准入项。
RRF 为什么只加名次不加分数？
BM25 打分十几分、余弦 0~1 分，量纲不同直接加权等于让量纲大的一路独裁。RRF 只用名次倒数 Σ1/(k+rank)，两份名单可以加，两台仪器读数不能加。
无据拒答怎么做的？
检索命中为空或门控全零时，拒绝分支焊在调生成器之前——『知识库未命中，拒绝编造』是检索合同不是客服话术；0 命中是出门失败，不是编造许可证。
分块怎么选？
三把刀：固定长度（尺子）、句法打包（句子）、递归降级（洋葱）。实测 17090 字符文本：固定 24 块/硬窗 25 块/递归 31 块含 3 个碎片——先清洗再切分，overlap 税约 14.3%。
第四级再搜没涨点，价值是什么？
并集保序下 @10 与融合逐条相同是恒等式——它的价值是稳定性（失败可诊断）与可审计（每轮查询留痕），这正是企业场景要的。
怎么防评测泄漏？
黄金集冻结不参与调参；三级指标全部带 bootstrap CI；失败样本（光合文档误入 Top-3）固化成回归锁。
这个项目最大的失败案例？
双漏题：BM25 和向量都没把金标排进前 10（在 11–20 名）——@20 能命中。它告诉我们漏斗有天花板，也告诉我们按需再搜的真正战场在深排。
