WhaleRAG 不是调一个现成 API 就结束的 demo。你要从 PDF 解析开始，自己实现语义切块、向量索引、双路检索、精排、引用标注、拒答门控。每一步都有代码、有实验、有「为什么这么选」的解释。

它有真实的企业出身。我们参考并提炼了曾为北美顶级金融独角兽交付的定制化 RAG 系统，那套系统支撑了上万份财报、风控文件的实时问答与可审计访问。这次把企业级架构理念「轻量化」，做成一套通用的 RAG 实战模板，核心能力一个没少——高速检索、低幻觉率、可追溯来源、可控生成。

对你来说，做完它你手上会多三样东西：一个能写进简历的项目、一份带置信区间的评测报告、一套能扛住面试追问的讲法。

02

项目出身

它不是教学团队凭空设计的练习题，而是从一个真实的企业交付项目里拆下来的。

Project Aurora（极光计划 · 化名），是我们为某北美顶级金融独角兽交付的那套系统的内部代号。客户需求很具体：投研团队要快速横跨上百份财报找证据，风控团队要求每个判定可回溯、可审计——监管在盯着，不能出错。

那套系统跑在生产环境里，支撑了上万份财报和风控文件的实时问答。它做的不是闲聊，而是让每份文件里的每个论断都能被找到、被引用、被验证。我们把其中最核心的检索-精排-引用-拒答链路完整保留，砍掉多服务部署、权限审计、私有化这些企业级包装，把它装进一台普通笔记本。

所以 WhaleRAG 里每个设计决策背后都压着一个企业场景：为什么拒答要做两道门控？因为风控场景宁可不答，不可编造。为什么答案必须带编号引用？因为监管要求可审计。这些不是「业界最佳实践」四个字，是被真实业务逼出来的设计。

企业版是多服务部署 + 权限审计 + 私有化，课程版跑在笔记本上。两者差的是部署复杂度，不是工程决策。

03

项目架构

把 RAG 想成一个图书管理员：你问他问题，他不靠记忆回答，而是先去书架找书、翻到具体那页、确认内容，再指着书上的段落告诉你答案。整套系统就是在教机器做这件事。

一次提问的完整链路：证据评估 → 双路召回 → RRF 融合 → 精排 → 引用 / 拒答，每一步都能单独讲透

它厉害的地方不在某一步特别新，而是企业级系统该有的四件事它同时做到了，而且每件都有数字或代码兜底。

检索准双路召回加精排，Recall@10 实测 0.991（220 题封存评测集）
敢拒答两道门控，知识库里没有就直说没有，不硬编一个答案
可追溯编号级引用，答案里每个论断都能点开回看原文块
可验证数字全部带口径：固定种子、受控候选池、bootstrap 置信区间

建库阶段（前四步）

① 解析：PyPDF2 把 PDF 里的文字抽出来。
② 切块：切块就是把长文档拆成小段。RecursiveCharacterTextSplitter 按 1000 字符一块切，相邻块重叠 100 字符，防止一句话刚好被切在边界上断掉。
③ 编号：每块分配唯一 ID，这是后面「引用可追溯」的地基。
④ 索引：每块文字用嵌入模型（把文字转成一串数字、让语义相近的文字数值也相近）变成向量，存进 Chroma 向量库，落盘持久化，重启不丢。

问答阶段（后四步）

⑤ 召回：两条路同时找。BM25 按词面匹配，你写「利润」就找含「利润」的块；向量按语义匹配，你问「赚了多少钱」也能找到写「净利润」的块。RRF（把两路的名次取倒数再相加）负责把两份排序合成一份。
⑥ 精排：bge-reranker 这类精排模型会把问题和候选块放在一起重新打分，从前 20 块里挑出最相关的 5 块。
⑦ 引用：生成答案时每个论断后面标 [1][2]，点编号展开对应原文块。
⑧ 拒答：两道门控，知识库里没有的内容直接说没有。

这八步不是看一遍就懂的抽象概念。每一步你都要写代码、跑起来、看到中间结果，才会明白 RAG 为什么被设计成这样。

04

项目亮点

从面试的角度看，WhaleRAG 值得深入的是下面八个工程设计。蓝标签是 JD 原话，黄标签是考点，四条带实测数字。

可审计 RAG Agent · 八个工程设计，四个带实测数字
01
双路检索与 RRF 融合

BM25 管词面命中，向量管语义改写，RRF 把两路名次取倒数相加合成一份排序。它解决单路检索的两类失效：同义改写查不到、罕见字符串查不准。逐题对拍里，向量路救回 BM25 漏掉的 21 题，词面路救回向量路查不到的 1 道歌词字符串题。

JD：向量检索（Embedding 选型 + Rerank 策略）工程化落地考点：单路为什么不够
02
两级排序：宽召回、窄输入

先宽召回 top-20 保证答案别漏，再用 bge-reranker 精排挑 top-5 送进生成，噪声和成本一起压住。Recall@10 实测 0.991。宽到多少、窄到多少，这个取舍本身就是能讲的工程判断。

JD：Rerank 策略工程化落地数字：Recall@10 0.991
03
编号级引用

答案里每个论断标 [1][2]，编号对应唯一文本块，点开回看原文和相关度。它解决「答案对不对没法验证」这个最要命的问题——面试官可以当场抽查任意一条。

JD：幻觉问题与处理考点：答案可验证
04
两道拒答门控

第一道：检索最高相关度低于阈值直接拒。第二道：生成答案里的引用编号对不上已有块，再拒一次。它解决「知识库里没有还硬编」——无据不编是企业场景的底线，不是加分项。

JD：置信度评估与幻觉治理考点：无据不编
05
检索 Agent Loop

评估首轮证据够不够 → 决定要不要再查 → 3 轮硬上限。任务规划、工具调用、多轮循环、停止条件在检索这个场景里的完整落地。实测平均 2.16 轮、65% 的查询触发二次搜索。

JD：基于 Agent Loop 实现任务规划、工具调用数字：平均 2.16 轮
06
封存评测集

MS MARCO 真实查询 220 题、候选池 1810 段落、随机种子固定 42；四种检索策略同口径对照，bootstrap 重采样 1000 次报 95% 置信区间。它解决「自夸不可验证」——谁重跑都是同一份数字。

JD：模型评测与 A/B 测试体系数字：95% CI
07
逐题分歧归因

每处检索分歧逐题人工对拍，得出 21/1/2/1 这组数；Hybrid 没超过 Dense 的负结果如实入档。它解决「只报好消息」——能回答「为什么融合反而降了」，比一个好看的分数有说服力得多。

JD：自动化评测 + 人工评审考点：负结果怎么讲
08
企业级链路轻量化

Project Aurora（化名）为北美顶级金融独角兽交付的检索-精排-引用-拒答链路，支撑过上万份财报与风控文件的可审计问答。课程版保留全部工程决策，只裁剪部署复杂度，所以你讲的是真实场景里的取舍。

八个设计串起来，你能展示的是一套覆盖检索融合、两级排序、可信回答、按需检索、效果验证的完整 RAG 工程。诚实边界：这类 JD 里还会写「多智能体协同」「分层记忆体系」，这两块由同系列项目覆盖——m2 做记忆系统、m4 做多 Agent 协作，本页不冒领。

09

实验证据

别人自夸，我们给数据。而且给的是「谁重跑都能拿到同一份数字」的口径。

评测方法

评测集用 MS MARCO v1.1（微软发布的真实搜索问答数据集，查询来自真实用户），取 220 条查询 + 1810 个段落构成受控候选池，随机种子固定 42——任何人重跑拿到的是同一份数据。两个指标：Recall@10 是正确答案进前 10 的比例，衡量「找没找到」；MRR@10 是答案排名倒数的平均，衡量「排得靠不靠前」。置信区间用 bootstrap（有放回重采样）跑 1000 次，取 2.5% 和 97.5% 分位报 95% CI。

四问四答 + 四种策略同口径对照：每个数字都附带验证方式

主结果

四行数字，跑在同一个 220 题评测集上：

BM25（纯词面检索）：Recall@10 = 0.900，MRR@10 = 0.456
Dense（向量语义检索）：Recall@10 = 0.991，MRR@10 = 0.536
Hybrid（RRF 融合）：Recall@10 = 0.986
Agentic（按需再搜）：Recall@10 = 0.986

负结果：Hybrid 和 Agentic 都没有超过 Dense

这是这个项目最诚实的一组数字。Hybrid 和 Agentic 的 Recall@10 都是 0.986，没超过 Dense 的 0.991。原因很清楚：220 题的小语料上 Dense 已经跑到 0.991，距离上限不足 1 个百分点，融合和再搜没有提升空间。逐题归因也对上了——Hybrid 相比 Dense 反丢 2 道题，因为 RRF 取名次平均，把表现好的那一路的好名次稀释掉了。

这组负结果的教育价值在于：技术的收益边界在语料规模。你学到的不只是「上融合会更好」，而是「上了不一定更好，以及怎么用实验把这件事证明出来」。面试时主动讲负结果，比吹一个「全面提升」可信得多。

逐题分歧归因（21 / 1 / 2 / 1）

向量路救回 BM25 漏掉的 21 道题——查询里有改写和同义表达，词面匹配直接失效；BM25 只救回向量路 1 道题——一道歌词字符串题，字面精确命中反而更可靠；Hybrid 相比 Dense 反丢 2 道题、补回 1 道；还有 1 道题两条路都漏了。每个数字背后都有具体题目和具体原因，是人工逐题对拍出来的。

检索 Agent Loop 的实测行为

让系统自己判断首轮证据够不够、要不要再查，上限 3 轮。结果是平均每条查询 2.16 轮，65% 的查询触发了二次搜索。这组数字说明两件事：多数查询一轮确实不够；但在这个语料规模上，多查一轮没能换来 Recall 提升。

一条口径纪律：评测链用 all-MiniLM-L6-v2，教学链用 Qwen3-Embedding-4B，两套链的数字不混用。你报告里写哪套，就用哪套的数。

常见问题

学生真实问过的几个问题。

需要自己的 GPU 吗？

不需要。嵌入、精排、生成三类模型都走 SiliconFlow API，注册即得免费额度。你需要的只是一台能跑 Python 的笔记本。

API 要花多少钱？

跑课程设计的教学链路和实验，免费额度基本够用。如果你自己加大语料规模重跑评测，嵌入和生成调用会产生少量费用，但不是一笔需要犹豫的钱。

基础差能学吗？

你需要会 Python 基础（函数、类、import），会装依赖、会看报错。不需要提前懂 RAG、向量、检索——文档里每个术语第一次出现都有大白话解释。如果你会调 API 但没写过完整系统，这个项目刚好补上从「会调」到「会做」的那一段。

需要自己从零实现吗，还是看源码就行？

两种都走得通。赶面试的同学可以沿「看 teacher 逐行讲解版 → 跑通 reference → 读懂评测与归因」这条线，重点是能讲清设计和数字。时间充裕的同学建议写 student 留白版，自己填 TODO，再对照 reference，理解会深一层。

和看论文、看博客有什么区别？

看论文你知道「有人提出过一种方法」。做 WhaleRAG 你知道「这个方法在 220 题上跑出来是多少、换一种变多少、为什么变、怎么验证」。区别就在你有没有自己跑过数字。

有视频教学吗？

没有手把手带做视频，核心材料是图文文档加三份源码，配飞书答疑群有问必答。喜欢先读方案、再看源码、最后跑验证的同学效率会很高；只能跟着视频逐行敲的同学，这个项目不适合。

做完到底能拿到什么？

三样：一个能写进简历的项目（完整代码加评测报告）、一套能讲 30 分钟并扛住追问的面试话术、一个你自己搭的知识库系统——换一批语料，它就是新场景下的新项目。

让数据自己开口说话

一条完整链路，一份带置信区间的评测报告，一套能扛追问的讲法。把简历上那句「熟悉 RAG」，换成「我亲手写过一套 RAG，并且知道它的边界在哪」。
