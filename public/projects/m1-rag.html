01

场景故事

从「能回答」到「可追责」：企业知识库中的实际工程问题

金融独角兽的投研团队每天面对几百页研报、公告与政策文件——分析师问「某标的最新风险提示在第几页、原文怎么写」，传统做法翻文档半小时；RAG 一次检索直接给答案并附句级引用，内审可逐句跳回原文。

这个项目的知识底座是 2841 行的 RAG 全链（teaching/streamlit_rag2：teacher 完整答案 + student 实现骨架）：PDF 解析、递归分块、Chroma 向量库、检索、重排、引用问答一应俱全；金融侧配 1146 行的 ReAct Agent（六工具查股价/基本面/历史/股息/财务/多标的对比）和 2214 行的五角色研报产线（协调者→基本面/技术/风险分析师→撰写者），reports/ 里有真实生成的 AAPL 研报。

检索质量用 220 题 MS MARCO 黄金集实测：四级漏斗（BM25→向量→RRF 融合→按需再搜）Recall@10 从 0.900 提升到 0.991；分歧表逐题归因（向量救词面 21 题）。多 Agent 侧实测对抗注入 10/10 拒绝、15 项事实检查全对——金融场景的两条底线：不编数字、不做投资建议。

可迁移场景：换行业语料三步走流程、法务合同库（条款级切分）、医疗指南库（引用等级）。

08

面试深挖预演

为什么定位金融场景？
金融场景对 RAG 有严格要求：数字错误会导致事故，引用必须句句可回原文，合规要求不做投资建议。三道发布门（检索回归/引用覆盖/无据拒答）在金融场景中是准入项。
RRF 为什么只加名次不加分数？
BM25 打分十几分，余弦 0~1 分，量纲不同直接加权会导致量纲大的分数主导结果。RRF 只用名次倒数 Σ1/(k+rank) 进行计算，通过排名而非原始分数进行融合。
无据拒答怎么做的？
检索命中为空或门控全零时，系统会在调用生成器之前执行拒绝分支。『知识库未命中，拒绝编造』是系统的检索规则。0 命中代表检索未得到结果，系统会直接拒绝回答以防止编造。
分块怎么选？
切分有三种方式：固定长度切、按句子边界切、先大段再逐层细切。实测 17090 字符文本的结果为：固定 24 块，硬窗 25 块，递归 31 块含 3 个碎片。采用先清洗再切分的流程，overlap 约 14.3%。
第四级再搜没涨点，价值是什么？
并集保序下 @10 与融合逐条相同是恒等式。它的价值在于提供稳定性以便于失败诊断，以及提供可审计性以实现每轮查询留痕。
怎么防评测泄漏？
黄金集冻结且不参与调参；三级指标全部带 bootstrap CI；失败样本（光合文档误入 Top-3）被固化为回归测试用例。
这个项目最大的失败案例？
两种检索均未命中：BM25 和向量都没把金标排进前 10（在 11–20 名），但 @20 能命中。这说明漏斗结构存在召回上限，按需再搜的核心环节在于深排。
