01

场景故事

从「聊完就忘」到「越用越懂你」：字节已设专职记忆岗的工程问题

用户上周说过「偏好保守方案」，这周客服 Agent 全忘了；换个会话，之前聊定的口味全白聊。失忆的根源不是没建库——是把临时状态、稳定偏好、噪声堆进了同一个容器。

这个项目按生命周期六问重构记忆：写什么过五维准入（「我在公司楼下」0.5178 仍判中期——排序器救不了准入，NOOP 必须独立存在）；何时写分热/冷/反馈三路径（「以后请用表格」词表判冷写、口语判热写，mismatch 当回归锁）；召回用 0.6 相似度+0.3 新鲜度+0.1 重要性，7 天衰减到 0.497。

遗忘不是 delete 一条路：过期是仍可查询的否定（版本化，Facebook→Meta 可回溯），删除是不可查询的否定（墓碑）；压缩过四维质量门 s≥0.5 才清空短期层——没有指针的压缩是删除披马甲。评测沙盘把收益拆开：无记忆 0/3，经验引导 2/3，经验在但资产不持久化 2/3 复用 0。

可迁移场景：陪伴产品长记忆、数字员工画像、多用户记忆隔离

09

面试深挖预演

NOOP 为什么必须独立存在？
「我在公司楼下」五维得分 0.5178 仍判中期——I 权重只有 0.2 时其余四项已托到 0.46，调权重救不了。排序器管好坏，准入器管进出，混在一起就是延迟爆发的垃圾堆。
摘要和压缩有什么区别？
摘要变精（内容轴：保留命题），压缩变密（体积轴：省 token）。中心节点必须带可展开指针，否则是删除披马甲——我们抽 88→15 token 的案例覆盖率失败，当回归锁保留。
过期和删除怎么分？
过期是仍可查询的否定：版本链保留，Facebook→Meta 可回溯；删除是不可查询的否定：墓碑位。「不再吃素」触发 DELETE 时连带删了奶制品偏好——过删案例保留当教学资产。
衰减公式怎么定的？
工程取舍不是行业标准：exp(−0.1×days) 让 7 天降到 0.497、30 天 0.05——近因够强、远期够淡，且可解释可调参。没有任何 JD 规定公式，JD 只说 ranking 与 forgetting。
跨会话记忆怎么评测？
三模式沙盘：无记忆 0/3、经验引导 2/3、经验在但资产不持久化 2/3 且复用 0——把『经验引导』和『资产持久化』两个收益拆开归因。
最大的坑是什么？
晋升与挤出的顺序：FIFO 先挤出后晋升，该留的「上周风控」就没了。生命线规则：晋升必须早于或同时于挤出。
和 mem0/Letta 什么关系？
我们实现了机制级最小版（四操作/衰减/版本化），mem0 开源库接入是 P0 扩充项——JD 把 mem0/memOS 贡献列为加分，路线是从使用者到贡献者。
