AgentAlpha · Agentic RL 训练台

基于 veRL 的 Agentic RL：训练会搜索的推理模型

将「搜索」由 prompt 技巧转化为模型能力。项目基于 veRL/EasyR1 复现 Search-R1，使用 GRPO 训练 3B-7B 模型学会何时推理、何时检索以及何时停止。这是后训练岗位的核心实战内容。

01

场景故事

企业知识问答的核心矛盾：是否搜索，让模型自行学习

DeepSearch 靠 prompt 让模型学会搜索，Agentic RL 靠训练：把搜索建模为 RL 的动作空间，模型在推理过程中输出检索调用、拿到检索结果作为观测继续推理，直到给出最终答案。奖励只看答案对不对、格式合不合规、检索用得省不省——搜索时机是模型自己学出来的。

项目沿技术演进线走：veRL 的 HybridFlow 抽象（rollout/reward/update 解耦、对接 vLLM/FSDP/Megatron）→ EasyR1 的多模态扩展与多算法（GRPO/DAPO/Reinforce++/ReMax/RLOO）→ Search-R1 的检索增强训练流程（arXiv:2503.09516）。训练细节是重头戏：retrieved token masking 防止模型从检索文本里抄答案（奖励捷径）、检索次数代价项平衡「不搜索」与「刷搜索」两个极端。

分析训练前后的行为变化：检索触发位置分布、平均检索次数、答案质量（F1/EM）——「模型学会在信息不足时才搜索」这件事本身可以被量化。

可迁移场景：工具调用 RL（任意工具）、企业私有知识库的检索增强训练以及多轮对话策略优化。

写进简历怎么写

基于 veRL/EasyR1 复现 Search-R1：3B 模型 GRPO 训练 400 步真实收敛（单卡 24G 显存跑完，峰值 14.7GB），留出集成功率从 0 提升到 0.05（配对 z 检验 p=0.0253）
设计复合奖励（答案对错、格式、检索次数代价），并用 retrieved token masking 堵住奖励漏洞：训练中识别并消除了「照抄检索文本」的作弊行为，奖励曲线稳定收敛
PPO 与 DPO 数值核实现（18 个测试用例）：PPO 含 GAE 优势估计、重要性比率裁剪、KL 锚定；DPO 含偏好对损失、reference 锚定、长度偏置审计，加上 GRPO 后训练全家桶算法齐备
08

面试深挖预演

GRPO 和 PPO 的区别？为什么 GRPO 不要 critic？
PPO 需要训练 value 网络计算 advantage，显存和稳定性成本较高。GRPO 对同一 prompt 采样一组回答，使用组内奖励的相对排名作为 advantage（减去组均值并除以组标准差），从而省去 critic。其代价是组大小会影响方差估计质量，组太小会导致 advantage 噪声大。
retrieved token masking 是什么？不做会怎样？
检索返回的文本拼接在上下文里，如果这些 token 参与策略梯度，模型会学会从检索文本里复制答案。这样虽然 reward 高，但模型没有学会搜索策略。masking 使梯度只作用于模型自己生成的 token。这是 Search-R1 系训练稳定的关键细节。
检索次数惩罚怎么调？
惩罚过重会导致模型完全不搜索，降低答案质量；惩罚过轻会导致模型每步都搜索，增加计算成本。具体的做法是将检索代价设为每次固定的小惩罚，并结合验证答案质量不下降的区间扫描。同时需要监控「零检索率」和「平均检索数」这两个异常指标。
多轮搜索交互怎么进训练 batch？
一次 rollout 是一条完整的多轮轨迹（推理→搜索调用→观测→继续推理→…→答案），检索结果作为环境观测拼接回上下文。在计算 loss 时，需要对观测 token 进行 masking。rollout 引擎（vLLM）负责生成并与检索系统交互，训练引擎只接收完整轨迹。veRL 的 rollout/update 解耦正是为此设计的。
训练崩了你怎么办？
首先观察三类信号：reward hacking（奖励上升但答案质量不升，通常是因为复制检索内容或获取格式分），熵塌缩（策略失去探索能力，观察 KL/entropy 曲线），以及长度膨胀（无限推理且不收敛）。对应的处理方法包括检查 masking、调整 KL 系数、增加长度惩罚或长度上限。
GRPO 训练崩了，按 DAPO 的思路怎么逐条排查？
通过观察三条曲线来定位具体问题：entropy 持续下降（熵坍缩）时，使用 Clip-Higher 为正优势提供更高的裁剪上限；组内零方差比例升高（全对或全错样本缺乏梯度信息）时，使用 Dynamic Sampling 进行过滤；响应长度膨胀并被截断（产生奖励噪声）时，使用 Overlong Filtering。此外，可以增加 Token-Level Loss 来替换序列级平均。这四项是字节 Seed DAPO 论文提出的改进，EasyR1 中提供了实现，可以运行对照实验。
veRL 的架构官方是怎么讲的？
包含四条核心内容：混合编程模型（单控制器灵活结合多控制器高效）、自动映射算法（智能规划）、3D 混合引擎（高效执行）、rollout 与训练分离部署（兼容 Megatron/vLLM/SGLang）。HybridFlow 论文报告其训练吞吐最高提升 20 倍。掌握这四条内容说明阅读了一手材料。
