AgentAlpha · Agentic RL 训练台

基于 veRL 的 Agentic RL：训练会搜索的推理模型

把「搜索」从 prompt 技巧变成模型能力：基于 veRL/EasyR1 复现 Search-R1，用 GRPO 训练 3B-7B 模型自己学会何时推理、何时检索、何时停——后训练岗位的核心实战。

01

场景故事

企业知识问答的核心矛盾：该不该搜索，让模型自己学

DeepSearch 靠 prompt 让模型学会搜索，Agentic RL 靠训练：把搜索建模为 RL 的动作空间，模型在推理过程中输出检索调用、拿到检索结果作为观测继续推理，直到给出最终答案。奖励只看答案对不对、格式合不合规、检索用得省不省——搜索时机是模型自己学出来的。

项目沿技术演进线走：veRL 的 HybridFlow 抽象（rollout/reward/update 解耦、对接 vLLM/FSDP/Megatron）→ EasyR1 的多模态扩展与多算法（GRPO/DAPO/Reinforce++/ReMax/RLOO）→ Search-R1 的检索增强训练闭环（arXiv:2503.09516）。训练细节是重头戏：retrieved token masking 防止模型从检索文本里抄答案（奖励捷径）、检索次数代价项平衡「不搜索」与「刷搜索」两个极端。

分析训练前后的行为变化：检索触发位置分布、平均检索次数、答案质量（F1/EM）——「模型学会在信息不足时才搜索」这件事本身可以被量化。

可迁移场景：工具调用 RL（任意工具）、企业私有知识库的检索增强训练、多轮对话策略优化

09

面试深挖预演

GRPO 和 PPO 的区别？为什么 GRPO 不要 critic？
PPO 要训练 value 网络算 advantage，显存和稳定性成本高。GRPO 对同一 prompt 采样一组回答，用组内奖励的相对排名做 advantage（减组均值除组标准差），省掉 critic。代价：组大小影响方差估计质量，组太小 advantage 噪声大。
retrieved token masking 是什么？不做会怎样？
检索回来的文本拼在上下文里，如果这些 token 参与策略梯度，模型会学会「从检索文本里抄答案」——reward 高但没学会搜索策略。masking 让梯度只作用于模型自己生成的 token。这是 Search-R1 系训练稳定的关键细节。
检索次数惩罚怎么调？
惩罚重了模型学会完全不搜索（答案质量崩）、轻了学会每步都搜（成本爆炸）。做法：把检索代价设为每次固定小惩罚 + 验证答案质量不掉的区间扫描；同时监控「零检索率」和「平均检索数」两个病态指标。
多轮搜索交互怎么进训练 batch？
一次 rollout 是完整多轮轨迹（推理→搜索调用→观测→继续推理→…→答案），检索结果作为环境观测拼回上下文；loss 计算时对观测 token 做 masking。rollout 引擎（vLLM）负责生成与检索系统交互，训练引擎只收完整轨迹——veRL 的 rollout/update 解耦就是为此设计的。
训练崩了你怎么办？
先看三类信号：reward hacking（奖励升答案不升，通常在抄检索或刷格式分）、熵塌缩（策略失去探索，KL/entropy 曲线）、长度爆炸（无限推理不收敛）。对应处理：检查 masking、调 KL 系数、加长度惩罚/上限。
GRPO 训练崩了，按 DAPO 的思路怎么逐条排查？
看三条曲线定位到哪一项：entropy 持续下降（熵坍缩）→ Clip-Higher 给正优势更高裁剪上限；组内零方差比例升高（全对全错样本没有梯度信息）→ Dynamic Sampling 过滤；响应长度膨胀被截断（奖励噪声）→ Overlong Filtering；再加 Token-Level Loss 换掉序列级平均。这四项是字节 Seed DAPO 论文的改进，EasyR1 里有实现，可以跑对照。
veRL 的架构官方是怎么讲的？
四条：混合编程模型（单控制器灵活 + 多控制器高效）、自动映射算法（智能规划）、3D 混合引擎（高效执行）、rollout 与训练分离部署（兼容 Megatron/vLLM/SGLang）。HybridFlow 论文报告训练吞吐最高提升 20 倍。答出这四条说明读的是一手材料。
