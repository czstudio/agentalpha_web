AgentAlpha · Multi-Agent Report Factory

研报工厂 · 多 Agent SOP 系统

不是复制模型几份，是把长链路改写成可审查的团队：四角色合同·六字段消息契约·轮次预算仲裁·FSM 非法边拒绝——异常恢复靠结构不靠重试。

01

场景故事

从「四个会说话的窗口」到「可审查的团队」：字节飞书在招的协作工程

没有消息契约、没有停止规则、没有局部回滚的所谓团队，只是四个会说话的采样器——大家都说了，却没人接手。多 Agent 要买的不是更多采样窗口，是专业化分工、只传消息、互相审查、可局部回滚的团队合同。

这个项目把协作拆成结构：Planner 只拆路径、Researcher 只取证、Coder 只落地、Critic 只判断（issues+pass）；消息六字段校验在理解之前（自由文本过不了 schema）；轮次预算墙杀永动机批评器（budget 6 时 n=6 靠墙停），信息增量耗尽才早停（budget 12 时 n=7 省 5 次生成）。

流程上升为 FSM：七条合法边之外的结构性跳转抛 ValueError——DONE 之后想改基本面？这条边不存在。研报工厂五角色铁律（协调者不做分析/分析师不爬数/撰写不拉行情）+ 数字进 source JSON 叙述拼 [source]：对抗注入 10/10 拒绝，15 项事实检查全绿。

可迁移场景：代码评审委员会、舆情联合会商、供应链对账协同

09

面试深挖预演

为什么 FSM 而不是自由 GroupChat？
自由对话里非法跳转只能『再说一遍』；FSM 里这条边不存在，抛 ValueError。异常恢复靠结构不靠再生成一次——月之暗面 JD 要的工作流引擎就是这个判断。
轮次预算和 token 预算什么区别？
轮次管交互深度（防永动机批评器），token 管经济账。budget 6 时靠墙杀停（n=6）；budget 12 时连续两轮无新问题才停（n=7 省 5 次生成）——停机谓词的次序本身就是契约。
怎么证明协作真的有效？
对照实验+假绿灯保留：第二轮终稿仍含『（漏了 Key 约束）』但 pass=true——另开角色是必要的不是充分的，谓词写窄照样放行，这当失败写进成绩单。
研报的数字怎么防编造？
三工人+主编的观测与叙述分离：数字只进 source JSON，叙述由程序拼 [source] 原始浮点——主编不读行情接口，没有改价通道。NVDA 214.72 对 K 线可复核。
什么时候不该用多 Agent？
工具少且不重叠、流程短、强依赖串行——单 Agent 更好。多 Agent 的价格是 15× token（对照栏数字），买之前先问值不值。
人工干预怎么落地？
MANUAL_REVIEW 是 FSM 的状态不是 wiki 的一句话：fix_attempts 超限自动转人工态，人工边必须可被一次失败点亮——点不亮的人工等于没有。
和 A2A/集群运行时的差距？
我们做单进程编排；美团 CatClaw 集群级运行时、A2A 协议是生产化下一层——诚实缺口，列扩充清单。
