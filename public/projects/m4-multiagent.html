AgentAlpha · Report Factory（P4）

研报工厂

五个角色协作，产出一份可读的研报文件。LangGraph 状态机把协作写成结构：七条合法边之外的跳转直接抛 ValueError，数字全部对账行情 JSON，对抗注入十条全拒。本页所有运行记录来自真实产物文件，可逐步回放。

01

场景故事

从「四个会说话的窗口」到「可审查的团队」：多智能体协作工程

没有消息契约、没有停止规则、没有结构约束的多角色对话，只是四个会说话的采样器：大家都说了，却没人接手。多 Agent 要买的不是更多采样窗口，而是专业化分工、只传消息、互相审查、结构可回滚的团队合同。

这个项目把协作拆成结构：调度器只分发、三个研究员各自只取一类证据（基本面 / 技术面 / 风险因子）、主编只做拼接与免责声明校验。流程写成 LangGraph 状态机：七条合法边（START→ORCH→FUND→TECH→RISK→SYNTH→DONE→END）之外的结构性跳转抛 ValueError，异常恢复依赖结构而不依赖重新生成。

研报的数字只进 source JSON，叙述由程序拼接 [source] 行中的原始浮点数；主编不接触行情接口，没有改价格的通道。对抗注入测试十条全拒（refusal_rate 1.0），五标的 15 项事实检查全部对账通过。

可迁移场景：代码评审委员会、舆情联合会商、供应链对账协同。

07

面试深挖预演

为什么 FSM 而不是自由 GroupChat？
自由对话中的非法跳转只能要求重新生成。在 FSM 中，如果边不存在，assert_legal_edge 直接抛 ValueError。本项目的非法边测试留了记录：DONE→FUND、SYNTH→FUND、ORCH→DONE 三条全部被结构性拦截。异常恢复依赖结构，不依赖重新生成。
怎么证明协作真的有效？
评测分两块：对抗注入 10 类各 1 次，判定标准是拒绝执行并保留免责声明，结果是 refusal_rate 1.0；事实核查是 5 个标的各 3 项数字与行情 JSON 对账，价格容差 0.05，结果 15/15。这两个数字都来自可回查的 JSON 产物，而不是文档宣称。
研报的数字怎么防编造？
观测与叙述分离。数字只进入 source JSON，叙述由程序拼接 [source] 行中的原始浮点数。主编不读取行情接口，没有修改价格的通道。例如 AAPL 报告里的 309.35 美元可以在 K 线上复核，data_source_test.json 记录了 yahoo_hit=true 与原始值。
什么时候不该用多 Agent？
当工具少且不重叠、流程短、强依赖串行时，单 Agent 更合适。多 Agent 的代价是每步都要走完整的消息传递与校验。本项目的上一站（投研速查助手）就是单 Agent 版本，两页可以对照着看拆分时机。
人工干预怎么落地？
这是当前诚实边界：LangGraph interrupt（人工审核态）还在规划中，页面没有放未跑的实验。现在的安全兜底是结构性的：免责声明校验不过就不出稿，非法边直接抛异常。
这个项目和单 Agent 版本的关系？
单 Agent 版（投研速查助手）验证工具契约与 ReAct 循环；本项目把它拆成角色产线并加上状态机。两边共用的行情工具已抽成统一适配器（unified_stock_adapter.py），换数据源只动适配器一层。
