01 · 项目介绍

大家好，今天带来一个新的 Agent 项目，叫《EverSelf》

今年阿里、字节、腾讯的 Agent 岗位 JD，要的不再是“会调 API”，而是一整套：记忆系统、Agent Loop、模型网关、Coding Agent、自进化、后训练和数据飞轮。这些东西零散地学，很难串成一段能讲清楚的项目经历，所以我们把它们做成了一个项目。

简单来说，EverSelf 是一个住在你自己电脑上的个人分身。你说过的话、让它做过的事，它都记着；下次干活直接用上；做错的事变成技能，下次不再犯；用得越多，它越像你。

图：EverSelf 能替你做的六件事

整个项目可以从四个维度来理解：

记得住

记忆怎么写、怎么存、怎么想起来、什么时候该忘。

做得了

Agent Loop、工具调用、沙箱、长任务续跑、模型网关。

学得会

自进化长技能；老师轨迹做 SFT，可验证奖励做 GRPO。

验得出

证伪账本、固定评测集、三臂对比、置信区间。

02 · 解决什么问题

这个项目解决什么场景问题？

你今天在 A 工具里跟 AI 聊了半小时：做电商项目、用 Python、不喜欢过度封装。明天换到 B 工具，一切从头讲。后天让它帮你比价买键盘，它又忘了你说过预算 500、只要静音轴。

图：每个 AI 都不认识你

直接把聊天记录全塞给大模型行不行？可以，但有三个问题：记录一长找不到重点；半年前说“用 Vue”后来改成 React，它分不清哪句是最新的；它答了一句话，你不知道依据是哪条记忆。

再往后还有更难的：任务跑到一半进程被杀了怎么办？它做错的事怎么保证下次不再错？怎么证明它真的变好了而不是碰巧？这些问题，一个成熟的 Agent 产品都要回答。EverSelf 就是把这些答案做成了代码。

项目核心功能有哪些？

图：八大核心能力

04 · 项目架构

项目架构怎么设计的？

整个系统分五层，口诀是：先记住，再做事，错了就学，学完要验。

图：EverSelf 五层架构

① 接入层

桌面 App、飞书、MCP 接口。你从哪里跟它说话，它都认得你。

② Agent 层

先判断你要做什么，拆成几步，再分发给代码、比价、股票、论文、深度研究这几类场景 Agent。

③ 记忆层

写入、检索、遗忘、溯源、同步都在这一层，所有 Agent 共用同一份记忆。

④ 执行层

模型网关、工具调用、技能库、沙箱、检查点。任务跑到一半被打断，能从上一步接着来。

⑤ 训练评测层

收集执行轨迹，筛出做对的，让小模型学（SFT），再用可验证的奖励继续训练（GRPO）；线上反馈回流成数据飞轮；每一轮都用固定评测集和证伪账本验收。

05 · 一次请求

一次请求是怎么走完整个系统的？

比如你说：“帮我给上次那个电商项目加个优惠券功能。”

图：一次请求的七步链路
理解意图判断是写代码任务，要项目背景
检索记忆找到电商、Python、不喜欢过度封装
规划任务拆成读、改、写测试、跑测试
沙箱执行每一步存检查点
验证结果测试没过带报错重试
带出处回答告诉你用了哪几条记忆
写回记忆新决定存下，失败的提炼技能
用户看到的是七步。工程上，这七步背后是三套机制：Agent Loop、模型网关、Coding Agent 双通道。下面三章逐个讲。
06 · Agent Loop

Agent Loop：一次任务的工程骨架是什么样的？

JD 里那串词：Agent Loop、任务分解、多轮工具调用、上下文构造、状态管理、失败恢复、结果验证、Tracing、实验评估。它们不是九个独立知识点，而是一个循环里的九个位置。

图：Agent Loop 工程骨架
任务分解把“加优惠券”拆成有依赖顺序的子步骤，每步有明确的完成判据。
上下文构造记忆、工具结果、对话历史拼成不超窗口的上下文；长对话用“固定块 + 摘要”，用户说过的数字和偏好逐字固定，摘要器碰不到。
多轮工具调用模型输出结构化调用，系统执行后把结果喂回去，循环直到完成或触发上限。
状态管理每一步的输入、输出、工作区快照都记在轨迹里，任何时刻可以回放到某一步。
失败恢复进程被杀从最近检查点恢复；非幂等工具靠工作区快照重放，不靠部分撤销。
结果验证代码跑测试、引用核原文、数字核来源，通不过不交付，而是带着报错重试。
Tracing整次执行每一步完整记录，可回放、可对比两次运行的差异。
实验评估固定评测集 + 回归基线 + 置信区间；改了 harness 之后，先看评测再合并。
07 · 模型网关

一次模型调用背后，工程上要管哪八件事？

所有 Agent 不直接调模型 API，统一走一个网关。JD 里的“LLM 应用研发技术栈”，说的就是这个网关要做的事。

图：模型网关要管的八件事
机制EverSelf 怎么做
模型路由意图识别、记忆分类走小模型；规划、写代码走大模型；某个模型不可用自动降级
流式输出边生成边显示；工具调用中途也能看到“正在读 orders.py”
工具调用统一的工具协议，模型输出结构化调用，网关校验参数后执行
Prompt Caching系统提示、技能说明这类固定前缀只算一次钱
Rate Limit按应用、按用户限流，超限排队重试，不让一个任务吃光配额
上下文窗口网关知道每个模型的窗口大小，超了先压缩再发
Token 计费每个任务一笔账，看得到哪一步最贵；按用户出配额
结构化输出要求模型按 schema 返回，格式不对自动重试
08 · Coding Agent

高频补全和长任务，为什么要分开设计？

JD 里常见一句：“针对低延迟高频请求和长任务 Agent 请求设计差异化的系统架构”。这两种请求的脾气完全不同，硬塞进一套架构里，两边都做不好。

图：Coding Agent 双通道
高频补全通道长任务通道
你在等什么敲一个字就要出结果，百毫秒级可以等几分钟，但不能出错
用什么模型小而快，走 Prompt Caching大而强，带工具
要不要沙箱不执行代码必须：读代码、改代码、跑测试、出 PR
断了怎么办重来一次就行从检查点恢复，工作区快照重放
怎么验收采纳率测试通过、PR 能合并

长任务通道从读代码到出 PR 全流程走通，每次任务的轨迹（看了什么、改了什么、测试结果）都进训练评测层，这就是后面“老师示范”的数据来源。

09 · 自进化

Agent 怎么自己变强，又不自己骗自己？

“自进化”听起来玄，拆开就是一个循环：跑任务 → 失败归因 → 提出改法 → 证伪检验 → 通过才启用。难的不是前三步，是后两步：怎么防止它把“碰巧变好”当成“真的变好”。

图：自进化飞轮与证伪账本
三种改法长出新技能（失败案例提炼成 SKILL）、调记忆策略（该存什么、召回几条）、改 harness 本身（提示、工具协议、循环上限）。
证伪账本每个候选改动先记一笔“它可能没用”的假设，用配对评测去推翻；推翻不了的才启用，推翻了的记下原因，防止同一个想法反复提。
退火预算早期允许大胆试，越往后评测花费越收紧；总预算用完自动停，避免无限改下去。
泄漏预筛候选改动如果只是把评测题答案塞进提示，预筛直接拒绝，不浪费评测额度。
噪声地板先测同一版本跑两次的差异，低于这个差异的“提升”一律不算数。
结构新颖度改动和现有版本太像的降权，鼓励真正不同的方向。
同一个内核同时管三件事：记忆策略自调优、技能准入、harness 改动。三处共用一套证伪规则，就不会出现“技能这边宽、记忆那边严”的双标。
10 · 后训练

怎么让小模型学会“什么时候该记、该查、该调工具”？

大模型很强，但它不知道你的记忆系统怎么用。靠提示词写规则很脆弱，更稳的办法是让小模型把这套行为学会。老师是大模型，教材是它跑出来的轨迹。

图：后训练五步管线
Teacher rollout大模型带着记忆和工具跑六类任务，每步记录：看到什么、读写哪条记忆、调什么工具、结果如何。
拒绝采样只留结果可验证为对的轨迹：测试通过、引用对得上原文、比价可复核。失败的进错题本，当对比样本。
SFT小模型照着合格轨迹学“何时写记忆、何时检索、怎么调工具”。LoRA，单张 4090 可训。
在线策略蒸馏（OPD）学生自己采样，老师逐步打分；多个老师意见分歧大的样本先放一边，不拿有争议的东西教学生。
过程奖励（PRM）不只看最终对错，每一步也打分：规则能验的步骤直接验，验不了的用蒙特卡洛估计；奖励经校准再用，防止分数虚高。
GRPO同一题答多次，按可验证奖励排序更新。奖励 = 任务成功 + 记忆命中 + 引用有效 − 成本 − 越权。
Reward hacking 告警故意构造钻空子的答案喂给奖励函数，给了高分就报警，奖励函数先改再训。
三臂评测原始 / SFT / SFT+GRPO 跑同一批记忆评测题，报告置信区间，不只报平均数。
11 · 数据飞轮

上线之后，用户每一次“采纳 / 打回”怎么变成训练数据？

训练不是一次性的。真正的数据来源是线上用户：采纳了什么、打回了什么、改了哪里。JD 里的“Online User Data Flywheel”和“Scaling Law”，说的就是这套循环怎么持续转。

图：线上数据飞轮与 Scaling Law 观察
三条回流通道采纳 → 训练样本；修改 → 偏好对（改前 vs 改后）；打回 → 先归因再分流。
badcase 自动归因打回的任务自动判断错在哪一层：检索没召回、推理错了、工具失败、还是奖励给错了。
动态评测集新出现的失败模式自动进评测集，老的通过率稳定的题退场，评测集跟着真实分布走。
回归基线每次再训练前后跑同一批题，任何一类题掉了都拦下，不让新模型“这边涨那边跌”。
Scaling Law 观察按数据量分档训练，画效果随数据量变化的曲线，看收益在哪里开始变缓，决定下一步是攒数据还是换方法。
查询合成线上数据不够时，用七类任务模板和五种变异合成新题，每条带溯源，和真实数据分开记账。

13 · 项目亮点

项目亮点有哪些？面试会怎么问？

图：十大项目亮点

为什么记忆不能只靠向量检索？

新旧冲突、时间顺序、溯源，相似度解决不了。检索之外再加一层冲突与时效判断。

JD：记忆生命周期考点：混合检索

怎么证明“自进化”不是自己骗自己？

证伪账本 + 噪声地板：先测同版本两次的差异，低于它的提升不算；新改动先试着推翻它。

JD：自进化考点：统计显著性

长任务进程被杀了怎么恢复？

每步存检查点，非幂等工具用工作区快照重放；在随机时刻注入 kill，对比恢复后与不中断运行是否逐字节一致。

JD：Durable Execution考点：检查点、幂等

长对话里用户说过的数字怎么不丢？

只靠摘要会静默丢数字。把用户说的数字、日期、偏好逐字固定成一个块，摘要器永远碰不到。

JD：上下文工程考点：压缩与保真

GRPO 的奖励怎么防作弊？

可验证奖励 + 过程奖励校准 + reward hacking 告警：故意钻空子的样例给了高分就先改奖励。

JD：强化学习考点：reward hacking

补全和长任务为什么要分开架构？

延迟、模型、沙箱、恢复、验收标准全都不同。

JD：Coding Agent考点：系统设计

Agent 被恶意指令带偏怎么办？

注入检测加沙箱：即使被骗，也只能在受限目录里动，不能联网外传。

JD：沙箱安全考点：Prompt Injection

用户反馈怎么变成训练数据？

采纳、修改、打回分三条通道；打回的先归因，再决定进训练集还是评测集。

JD：数据飞轮考点：数据闭环

常见问题

我是零基础，能学吗？

能。每个术语第一次出现都有大白话解释。建议顺序：先跑通记忆内核，再看 Agent Loop 和网关，然后自进化，最后训练。

自进化和后训练有什么区别？

自进化改的是技能、策略和 harness，不动模型权重，几分钟一轮；后训练改的是模型权重，几小时一轮。两者共用一套评测和证伪规则。

炒股会不会替我下单？

不会。只做数据查询和分析，结论带出处，不接交易接口。

购物比价能覆盖所有平台吗？

项目给你一套可复现的比价流程：怎么采集、怎么对比、怎么给每个价格标来源。平台范围由你扩展。

为什么要有证伪账本？

自进化最容易自己骗自己：测几次碰巧变好就说有效。账本强制先试着证明“没用”，证明不了才算数。

有多模态记忆吗？

当前版本以文本记忆为主，多模态记忆是后续扩展方向。
