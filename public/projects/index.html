产品形态交付

每个项目包含界面、指标面板和可演示的运行过程，便于面试官在三分钟内了解你的工作。每章教程配有五道深挖题与答题要点。

五大自研引擎（2026-10 新增）

我们在真实工程项目里沉淀的五个可复用引擎：价值信号校准引擎（发现内部成功信号会反向追踪表面指标——管线自动校正）、任务环境合成流水线（64/64 三段校验全过）、状态外置搜索框架（多面检索 R@5 0.517 vs 0.350，p=0.022）、查询改写训练器（实测并绕开 Goodhart 塌陷）、自进化安全栏（噪声地板/成本规则/泄漏预筛，让自动优化不伤线上）。这些引擎你在项目里直接调用，也可以带走改造成自己业务的组件。

上线级工程护栏

大厂和课堂最大的差别是护栏：每条自动化优化都要过噪声地板、显著性闸、泄漏预筛三道门才准上线；九条真实工程教训（预算伪影、指标饱和、护栏拦截）全部写进台账——你学到的不是跑通，是敢不敢拦。面试官问「上线怎么保证不翻车」，你有一整套自己拦过的案例。

05

五大自研引擎：真实工程里长出来的可复用组件

不是框架教学，是我们在自己的数据管线和自动优化系统里反复迭代出的引擎——每个都有实测数字、失效模式和护栏。学完可以把引擎整个带走，改造成你业务里的组件。

01价值信号校准引擎

解决什么：模型的内部成功信号会「说谎」——表面漂亮的输出拿到更高自信，正确答案反而被打低分。
怎么做的：自评坐标提取 + 三重对照校验（随机基线/反向供体/任务内配对）+ 上线前自动校正。
实测：反向追踪在 12 任务簇级 p=0.0005 显著；校准后错例自评平均下移。失效模式：信号与结果词面强相关时判别力会被词面解释——已在文档写明边界。

02任务环境合成流水线

解决什么：训 RL 没有可验证环境——手工出题慢、质量不稳、难度不可控。
怎么做的：四任务族参数化生成 + 上下文/难度双轴演化 + 三段验收（可构建/参考解可过/错解必拒）。
实测：64/64 三段全过；难度轴把 7B 模型 pass@1 从 0.500 压到 0.000（配对 p=0.0078）；对 SETA 开源 1013 个真实任务做了兼容校验。失效教训：评测预算 40-token 会把「更难」误判成「不会」——已写进协议。

03状态外置搜索框架

解决什么：把搜索状态全塞进上下文，多面查询下注意力稀释、小模型丢细节。
怎么做的：候选池/重要性策展/证据链接/验证记录/预算渲染全部外置给框架，模型只做四个语义决策。
实测：多面查询 R@5 0.517 vs 单发 0.350（配对置换 p=0.022）；去词面消融显示策展项贡献主要增益——边界如实写明，不吹「一个框架解决一切」。

04查询改写训练器

解决什么：检索查询质量靠人肉试 prompt；自动训练改写器又容易「为奖励走捷径」。
怎么做的：分档阶梯奖励 + 格式门控 + 长度锚定 + Goodhart 检测（奖励饱和时辅助惩罚会接管——实测并在管线里拦住）。
实测：复现了完整失效链（0.878→0.805）并给出修复方向；格式冷启动必须预热（0/256 合法率实测）——这两个坑你不用再踩。

05自进化安全栏

解决什么：让 Agent 自动优化自己，最大的风险是「优化了个寂寞」：在训练题上涨分、上线就失效。
怎么做的：噪声地板（增益低于评测方差不放行）+ 成本规则（新增推理开销必须被增益覆盖）+ 泄漏预筛（题面泄漏在评估前拦截）+ 剪枝。
实测：正则化版本在 held-out 上保留增益的能力显著优于裸贪心基线；这就是我们 EvoAgent 平台 GateClimb 三闸的完整版。

+引擎怎么用

每个引擎 = 一个 ≤400 行的纯 Python 模块 + 全套测试 + 一键实验脚本 + 失效台账。你可以：直接调用 / 改成自己业务的组件 / 当成面试里「我造过轮子还知道它哪里会坏」的证据。全部源码在仓库里，无黑盒。
