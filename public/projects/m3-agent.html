01

场景故事

从「调 API」到「上百轮工具调用的稳定性」：应用层 Agent 的五件套

模型流畅地答完了——但没调工具、没查数据、没验事实。「我以为调过了」是所有工具调用事故的根：模型只生成任务单（Generated），系统才执行（Executed），两个谓词混淆，缺参/超时/权限三种病就会被同一招『重试』耽误。

这个项目把契约做进循环：思考产出『动作+参数或 Finish』，观察必须真返回且写回；错误三分类——模型层错改任务单不重试、瞬时错误限次重试 K=3、确定性错误停。缺 city 参数的观察是『缺少必填参数』而不是异常栈；`pow` 被枚举拦在重试循环外。

金融场景加四道闸：入口门闩拒预测股价（工具环 0 次）、先查再比（两次独立观察）、失败句禁 or-0 兜底、出口『非投资建议』声明。8 工具场景下角色路由把「搜一下销量」从单路选错（0.75）修到全对（1.0）——何时拆多 Agent 的决策点。

可迁移场景：HR 制度问答、智能工单分派、运维告警处置

09

面试深挖预演

为什么错误要分三类？
缺参是任务单写错了（改单重发），超时是环境抖动（原样重试 K=3），权限/除零是确定失败（停）。全叫『重试』会把改单的病用重试治，越治越错。
反思和『再检查一遍』有什么区别？
『再检查一遍』是同一条分布的续写——选手兼裁判。独立批评器只交问题列表（每条带维度/问题/修法），且谓词写窄了照样放行：我们终稿保留『快很多』漏扫，10 分是规则眼里的满分不是无伤。
什么时候该拆多 Agent？
三个信号：工具过载（近义工具比正交工具更危险）、审查需要独立上下文、子任务异构指令。工具少不重叠、短流程就别拆——15× token 是多 Agent 的价格。
MOCK 数据会不会被问穿？
JD 要的是契约与稳定性设计。MOCK 锁行为边界（AAPL 190.0/MSFT 410.0 锁死），换 yfinance 只换数据源层；『夹具先行』本身就是工程素养。
合规四闸最容易被忽略哪个？
出口声明——比较答完不声明，叙述会被当成建议。『MSFT 市值更大（非投资建议）』的括号不是装饰，是责任边界。
AutoGen 学到什么？
类名不是协议，协议是 MayExec 落在谁头上：0.2 的 Assistant 规划/Proxy 执行，0.4 把工具收进 Assistant——设计在变，职责分离的问题不变。
这个模块和 workflow 何时二选一？
分支可枚举、流程确定 → workflow（便宜可审计）；需要模型自主决策动作序列 → Agent。判断错了要么浪费 token 要么丢失能力。
