## 1. 一面真题：MCP 由哪几部分组成

**问法**：「说说 MCP 由哪几部分组成？」

错误示范：答「Client 和 Server 两部分，跟 HTTP 接口差不多」。面试官立刻追两个点：Host 是什么角色？Server 能暴露哪些东西？

答题要点，按三层组织：

1. **角色层**：Host 是宿主应用（Claude Desktop、Cursor 这类），Client 是 Host 里负责和一个 Server 通信的模块，一个 Host 可以同时连多个 Server。Host 和 Client 不是一回事。
2. **能力层**：Server 暴露三类东西，Tools 是有副作用的操作，Resources 是只读数据，Prompts 是预定义的提示词模板。把只读数据和有副作用的操作混在一起说，是这题最常见的扣分点。
3. **协议层**：消息格式统一 JSON-RPC 2.0；传输方式本地用 stdio，远程用 Streamable HTTP（早期的 HTTP+SSE 双端点方案在 2025 年 3 月的规范更新里标记为 deprecated）。

**追问链**：「传输方式和消息格式为什么要解耦？」答：消息协议不变，传输通道可以按部署形态换，本地子进程不需要开端口走网络，这是 MCP 能同时覆盖本地工具和远程服务的关键。

## 2. 二面真题：MCP 和 Agent Skill 的区别

**问法**：「MCP 和 Agent Skill 有什么区别？」

错误示范：答「都是给 Agent 加能力的，格式不同」。面试官会反问：如果差不多，为什么要搞两套？

答题要点：两者不是竞争关系，是分工不同。

- **MCP 解决「Agent 怎么获得外部能力」**：把数据库、API、文件系统封装成标准化服务，Agent 连上就能用，解决从无到有的问题。
- **Skill 解决「Agent 拿到能力之后怎么把事情做对」**：把完成某类任务的知识和流程打包成可复用模块，是一个包含指令、脚本、模板、参考文档的完整文件夹，能被 Agent 自动发现和按需加载。

一句话分工：MCP 给 Agent 配电脑和软件，Skill 给 Agent 发操作手册。实际系统里两者同时工作，Skill 定义流程，流程里调用 MCP 提供的工具。

**追问链**：「为什么 Skill 不做成 MCP 里的一种 Tool？」答：Tool 的粒度是单次可调用操作，Skill 的粒度是一整套任务流程和判断标准，硬塞进 Tool 会让描述爆炸且丢失按需加载的结构。

## 3. 一面真题：更复杂的 RAG 范式

**问法**：「除了基本的检索加生成，你了解哪些更复杂的 RAG 范式？」

错误示范：答「Advanced RAG 加个 Rerank 和 Query 改写就到头了」。面试官直接点出你不知道 Self-RAG、CRAG、Agentic RAG。

答题要点，按演进讲，每种说清「解决了什么问题」：

| 范式 | 解决的问题 | 核心机制 |
|---|---|---|
| Naive RAG | 基线 | 检索、拼提示词、生成 |
| Advanced RAG | 固定流程里每环节做得更好 | Query 改写、混合检索、Rerank |
| Self-RAG | 该不该检索、检索质量谁来判断 | 模型自主决策检索时机并自评检索质量 |
| CRAG | 检索质量差时硬答 | 检索质量评估，差时降级到网络搜索纠错 |
| GraphRAG | 全局性问题局部检索答不了 | 知识图谱加社区发现、层次摘要 |
| Agentic RAG | 复杂问题一次检索不够 | 把 RAG 做成 Agent，多轮动态检索 |

**追问链**：「Agentic RAG 和带检索工具的 Agent 有区别吗？」答：前者把「检索-评估-再检索」做成系统的固定循环结构，后者检索只是 Agent 工具列表里的一项，调用与否全靠模型决策；工程上前者更可控，后者更通用。

## 4. 复盘与准备清单

- 百度这类考法的准备方式：每个核心概念写四句话——定义、组成、解决什么问题、和近邻概念的区别。四句话里任何一句含糊，追问就落在那一句上。
- MCP 的三层组成（角色、能力、协议）是 2026 年各厂通考题，百度问得最细。
- RAG 范式演进要能说出每种范式解决的问题，只背名字会在第一层追问就暴露。
