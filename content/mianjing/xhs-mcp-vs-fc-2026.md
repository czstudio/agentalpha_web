## 1. 真题：MCP 和 Function Calling 有什么区别

**问法**：「聊聊 MCP 和 Function Calling 的区别。」

错误示范一：答「MCP 是 Function Calling 的升级版，以后工具调用都走 MCP」。面试官指出：MCP 底层离不开 Function Calling，两个不是同一层面的东西。

错误示范二：答「就是包了一层壳，功能没本质区别，写法不一样」。面试官反问：如果只是写法不一样，Anthropic 为什么要专门设计一个协议？

答题要点，按层次讲：

1. **Function Calling 是「调用语言」**：定义模型怎么表达「我要调哪个函数、参数是什么」——解决单次调用的格式问题，模型输出结构化的调用请求。
2. **MCP 是「工具生态协议」**：定义工具怎么标准化打包、注册、被 AI 客户端自动发现——解决工具的管理和复用问题。
3. **依赖关系**：MCP 底层还是靠 Function Calling 驱动工具调用，它是在其之上的工具管理框架。淘汰说不成立。

实操层是加分项：用 Claude Desktop 配过文件系统或 GitHub 的 MCP Server 的话，把「配置文件加几行、自动发现工具、不用写对接代码」说出来，这道题就从背概念变成有体感。

**追问链**：「为什么有了 FC 还需要 MCP？」答：能调工具和管好工具是两回事——十几个工具散在各项目里各写各的 schema，版本、认证、复用全乱；MCP 把工具做成独立服务，实现一次到处复用。

## 2. 复盘与准备清单

- 层次辨析题的通用答法：先说「它们不在同一层」，再分别定义，最后说依赖或配合关系。直接对比功能差异会掉进题目的陷阱。
- 小红书的 AI 岗偏应用和内容场景，概念题之后常接「你会怎么用在社区内容工具上」，备一个内容审核或笔记工具的设想。
