## 1. 追问链拆解：23 问是怎么串起来的

**主线前半：概念依赖链**

什么是 Agent → 为什么需要工具 → Function Call 是什么 → MCP 的组成 → Function Call、MCP、Skill 三者对比 → Skill 的特性是什么。

这条链的考法很讲究：每个概念都从上一个概念的「没解决的问题」里长出来。Agent 能对话但动不了外部系统，所以需要工具；模型表达调用用 Function Call，但工具接入碎片化，所以有 MCP；有了工具但不知道按什么流程用，所以有 Skill。答的时候把这条因果说出来，而不是逐个背定义。

**主线后半：工程兜底**

怎么写好一个工具（描述清楚功能边界和参数）→ 调用失败的重试策略 → 保底工具（fallback）设计 → 结果溯源（每个结论能追到哪次调用）→ 可观测工具选型（langsmith 和 langfuse 的对比：自部署、trace 粒度、成本）。

**支线：上下文工程**

上下文的保存、隔离、选择、压缩四件事分别怎么做 → 上下文污染是什么（无关信息混入影响生成）→ 提示词工程和上下文工程的区别（前者改指令，后者管理模型能看到什么）。

**终局题（本场最狠的一问）**

「Agent 系统中工具调用失败怎么办？以及之前可能铺垫了哪些问题，串讲。」

这题在考体系感：重试、降级、澄清、fallback、溯源这些点你前面都答过，能不能意识到它们是一套失败处理体系，并按「事前预防（工具描述质量）→ 事中处理（重试降级）→ 事后追溯（日志溯源）」串成一条线讲出来。

## 2. 高频失分点与答法

1. **概念对比题答成名词解释**。「三者对比」要给维度：Function Call 是模型侧的调用表达，MCP 是工具侧的接入协议，Skill 是流程侧的知识打包——侧不同，不冲突。
2. **上下文工程答成「记住历史」**。面试官要听四件事：保存什么（什么信息值得进上下文）、隔离（多会话/多用户怎么分开）、选择（token 预算不够时留什么）、压缩（什么时候触发摘要）。
3. **失败处理只答「重试」**。重试只是事中一环；主动把降级（fallback 到只读能力）、澄清（向用户确认）、熔断（连续失败停止调用）、溯源（日志记录每次调用）说出来，这题才算答完。

## 3. 复盘与准备清单

- 链式面试的准备方式：把 Agent 概念图连成网，每条边能说「A 解决了 B 没解决的什么问题」。
- 阿里系的实习面偏爱「串讲」型终局题，练习方式是每学完一个主题，用自己的话 60 秒串一遍。
- 本场无手撕代码，但同期的淘天 Agent 线有手撕多头注意力，准备时别只练八股。

相关题目：站内题库的「MCP 是什么」「Agent Skill 是什么」「工具调用失败怎么兜底」都对应这场面试的原题。
