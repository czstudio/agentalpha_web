## 先这样答

客服适合工作流，营销适合 ReAct，商家运营适合状态机，研发助手适合带规划的 ReAct。选择标准是任务的确定性。确定性高的任务不要引入 Agent，避免增加不确定性。

客服的问答路径固定居多。用工作流串起检索就够了。热点问题还可以做成模板。营销内容生成的开放度高，任务经常需要结合外部工具调整结果，所以更适合 ReAct 加工具。

商家运营通常有明确的状态流转，例如审核、结算。状态机能把每个状态和转换条件写清楚，处理这类流程最稳。研发助手面对的任务复杂多变，不能只依赖固定路径。它适合使用 ReAct 加规划，让模型根据当前任务动态拆解。

## 面试官会怎么追问

- **「为什么客服场景不用 ReAct？」** 客服问答路径固定居多，热点问题也比较模板化。工作流加检索已经能覆盖主要处理过程。此时引入 ReAct，反而可能增加不确定性。

- **「营销和研发助手都用 ReAct，两者有什么区别？」** 营销主要需要调用工具来完成开放度较高的内容生成。研发助手的任务更复杂，也更容易变化。它除了使用工具，还需要加入规划，允许模型动态拆解任务。

- **「商家运营为什么选择状态机，而不是工作流？」** 商家运营包含审核、结算这类强状态流转。状态机能明确表示当前状态和下一步转换。流程边界清楚时，状态机比引入 Agent 更稳。

## 回答的坑

- 不要因为问题看起来复杂，就把客服这类确定性高的任务直接交给 Agent。
- 不要把营销、研发助手都只回答成“用 ReAct”，要分别说清工具和规划的区别。
