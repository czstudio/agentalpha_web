## 先这样答

Agent Skill 是把「指令、脚本、模板」一体化打包成可复用能力包的机制，关键在三点：Agent 能自动发现它、按需加载它、在需要时调用里面的脚本和资源。每个 Skill 是一个文件夹，核心是一份 SKILL.md 指令文件，可以带上脚本、模板、参考文档。Anthropic 在 2025 年 10 月推出 Agent Skills，同年 12 月把规范作为开放标准发布。

和普通 prompt 的区别：prompt 靠人手动复制粘贴，每次新对话重贴一遍，团队十个人贴十个版本，标准没法统一；Skill 被 Agent 自动发现和加载，版本统一、按需触发，不依赖人工流程。

和 MCP 的区别：MCP 解决「Agent 怎么获得外部能力」，把工具和数据标准化封装；Skill 解决「拿到能力之后怎么把事情做对」，是知识和流程的打包。一个给电脑和软件，一个给操作手册，实际系统里两者配合工作。

## 面试官会怎么追问

- **「按需加载是怎么实现的？」** 模型先只看到每个 Skill 的名称和描述，判断与当前任务相关时才加载完整内容进上下文。这是渐进式加载：全量塞入浪费上下文，按需加载要求描述里写清触发条件。
- **「为什么不把所有指令全写进系统提示词？」** 上下文窗口有限，几十个任务的指令全量进入会挤占工作空间并稀释注意力；Skill 把指令的存储和加载时机分离，用多少取多少。
- **「Skill 里的脚本和 MCP 工具有什么不同？」** 脚本随 Skill 分发、面向单一任务流程，MCP 工具是独立服务、面向通用能力复用；一个跟着流程走，一个独立部署。

## 回答的坑

把 Skill 说成「保存下来的 prompt」或「高级提示词模板」，忽略了自动发现和按需加载这两个机制，这题就只剩一半分。

说不出 Skill 和 MCP 的分工，两者混为一谈是这题最典型的挂法。
