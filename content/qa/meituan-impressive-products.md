## 先这样答

我会选 Claude Code、Perplexity 和 Cursor，按产品设计来讲它们为什么让我印象深刻。我不把它们当成产品名单，而是分别说明它们解决了什么问题，以及交互上做对了什么。

Claude Code 让我印象深刻，是因为它把上下文工程放进了产品体验里。它解决的是大模型在实际任务中如何获得合适上下文的问题。对我来说，好的地方不只是模型本身，而是产品围绕上下文来设计使用方式，让上下文服务于当前任务。我会结合自己的使用过程，讲清楚上下文如何被组织，以及这种设计为什么有用。

Perplexity 的特点是把搜索整合进大模型产品。它解决的是用户需要搜索信息，又希望直接获得模型整理后的回答这个问题。Cursor 则让我关注补全交互。它解决的是工程师写代码时，需要连续获得符合当前编写过程的补全。两者都没有只展示模型能力，而是把能力放进具体交互里。我的回答会停在自己真正用过、能讲清楚的部分，不会为了显得了解更多而罗列一长串产品。

## 面试官会怎么追问

- **「你为什么选这三个产品，而不是直接列出更多产品？」**
  我会优先选择自己真用过的产品。面试回答需要说明产品解决了什么问题，也要说明交互上做对了什么。没有深度使用过的产品，我不会只凭印象评价。

- **「你说 Claude Code 的上下文工程，具体想从哪几个角度讲？」**
  我会讲上下文如何进入产品使用过程，以及它如何服务当前任务。重点不是重复产品名称，而是说明上下文设计怎样影响使用体验。我会结合自己的实际使用来回答，不凭空补充没有观察过的细节。

- **「Perplexity 和 Cursor 的产品设计，区别在哪里？」**
  Perplexity 的重点是搜索整合，把搜索和模型回答放在一个使用过程中。Cursor 的重点是补全交互，让模型能力贴近写代码的过程。一个围绕信息获取来设计，一个围绕代码编写来设计。

## 回答的坑

- 只报产品名称和模型能力，却没有说明产品解决了什么问题，以及交互上做对了什么。
- 没有真正使用过产品，却照着网上的评价罗列功能，追问两句就无法展开。
