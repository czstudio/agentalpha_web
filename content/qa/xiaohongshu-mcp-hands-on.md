## 先这样答

接入一个 MCP Server 要写多少代码，先看你说的是哪种接入。用 Claude Desktop 配过文件系统或 GitHub 的 MCP Server，通常只要在配置文件里加几行。配置好后，客户端会自动发现工具。这个过程不需要自己写一段对接代码。所以，如果面试官问的是这种实操，我会直接回答：可以不写对接代码，主要工作是完成配置并确认客户端能发现工具。

这题问的不只是代码行数。面试官也在确认你是不是真的动手配过。回答时，我会把场景说具体，明确讲自己用 Claude Desktop 配过文件系统或 GitHub 的 MCP Server，再说明配置文件加几行、客户端自动发现工具、不用写对接代码。只说“看过 MCP 的介绍”或“知道它能连接工具”，没有回答接入时实际做了什么。面试官追问配置过程时，也很难继续展开。

面试时不要把结论说成所有 MCP 接入都不需要代码。这里的回答范围是用 Claude Desktop 配置文件系统或 GitHub 的 MCP Server。围绕这个场景讲清代码量和工具发现过程，就能回答“接入一个 MCP Server 要写多少代码”。这题考体感。答不出实操细节，说明只看过文章，不能把阅读过概念说成亲手接入过。

## 面试官会怎么追问

- **「你实际配的是哪种 MCP Server？」**  
  我用 Claude Desktop 配过文件系统或 GitHub 的 MCP Server。我的回答限定在这个接入场景。配置文件里加几行，客户端会自动发现工具。

- **「那你自己写了多少对接代码？」**  
  这个场景里，我没有写对接代码。主要操作是在配置文件中补上几行。之后由客户端自动发现工具。

- **「你怎么判断自己是真的跑通过？」**  
  我会说明自己在 Claude Desktop 里配置过文件系统或 GitHub 的 MCP Server。接入时，我关注配置是否完成，以及客户端是否自动发现工具。只读过文章，不能说成自己做过这次配置。

## 回答的坑

- 只回答“配置文件加几行”，却说不清客户端会自动发现工具，容易显得只记住了结论。
- 把这个场景说成所有 MCP Server 都不需要写代码，会超出题目给出的事实范围。
