## 先这样答

结论是，Agent 要根据动作的可逆性和成本决定追问还是继续。低风险、可逆的任务可以采用默认值。高风险、不可逆的任务必须先追问。

查资料、生成草稿这类任务，通常可以先按默认值继续。默认值应来自用户历史和业务配置，不能让模型自行猜测。Agent 完成后要展示自己采用的假设。用户可以直接纠正，或者补充要求。这样能减少不必要的等待，也能让用户看见 Agent 的判断依据。

下单、发送内容、修改生产配置这类任务，可能造成较高成本，而且不容易撤回。Agent 在执行前必须问清关键缺失项。追问也要有节制。一次问题应尽量覆盖决定执行所需的信息，不能把一个任务拆成连续多轮小问题，把用户问烦。这道题来自阿里宝典真题，核心不是追求永远谨慎，而是让确认成本和执行风险匹配。

## 面试官会怎么追问

- **「如果用户没有提供明确的默认值，你还会继续执行吗？」**  
低风险且可逆的任务，仍可以继续，但默认值要优先从用户历史和业务配置中取得。没有依据时，不能让模型凭感觉猜。若任务高风险或不可逆，就应先问用户补齐关键条件。

- **「可逆性和成本不一致时，你按哪个标准判断？」**  
两个因素都要看，不能只看动作是否能撤回。可逆但成本很高的动作，也需要更谨慎地确认。最终要判断执行错误的代价，以及动作能否恢复。

- **「怎样避免 Agent 因为追问太多而影响体验？」**  
先区分哪些信息真正影响执行结果。把关键缺失项集中到一次追问里，拿到回答后再执行。低风险任务则先用有依据的默认值继续，并把假设展示出来。

## 回答的坑

把所有模糊需求都交给用户确认，会让 Agent 失去处理低风险任务的效率。

为了省事让模型自行猜默认值，会在关键条件错误时造成不必要的成本。
