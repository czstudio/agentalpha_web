## 先这样答

Agent 解决的是复杂任务中的动态执行问题。它会根据中间结果决定下一步，调用工具改变外部世界，还能用记忆保留跨会话信息。

直接用大模型，只能生成回答。它没有工具时不能执行动作，也没有状态时不能持续记住任务过程。它可以告诉你该怎么做，但不一定真的完成任务。

纯 workflow 把路径提前写死。只要输入和预期不同，流程就可能走不下去。比如，用户先让系统处理一个请求，系统查到中间结果后，用户又要求根据这个结果改做另一件事。固定 workflow 很难临时改路径，也很难处理原流程没有覆盖的输入。Agent 会读取当前结果，再选择下一步，并在需要时调用工具。它的增量就是动态决策、工具使用和记忆，而不是单纯换一种调用大模型的方式。

## 面试官会怎么追问

- **「既然 workflow 更可控，为什么还要用 Agent？」**  
workflow 适合路径稳定、规则明确的任务。任务经常出现意外输入，或下一步必须依赖当前结果时，固定路径就会受限。Agent 可以在约束范围内根据结果选择后续动作。

- **「Agent 和直接调用大模型的边界在哪里？」**  
直接调用大模型主要解决理解和生成问题。Agent 还要处理行动过程，包括选择下一步、调用工具和保存记忆。需要改变外部世界或跨会话延续任务时，单独调用大模型不够。

- **「你会怎么判断一个任务该用哪种方案？」**  
如果任务只需要一次回答，可以直接用大模型。如果步骤固定，就优先考虑 workflow。如果任务需要根据中间结果调整路径，还要调用工具或保留跨会话信息，就考虑 Agent。

## 回答的坑

- 不要把 Agent 说成更会聊天的模型，重点要放在动态决策、工具使用和记忆上。
- 不要只说 workflow 不灵活，要给出一个中间结果改变后续路径的具体例子。
