## 先这样答

要同时管住委派路径、任务认领和 Token 预算，分别用检测、登记和限额控制三类风险。

先看循环委派。系统记录每次任务派发经过的节点。相同任务再次回到已经处理过的节点时，系统立即告警。系统还要设置委派深度上限，避免任务不断向下转交。

再看重复执行。系统为任务和结果做全局登记。Agent 认领任务前，先查询登记表。任务已经被处理，或者结果已经存在时，就不再重复执行。这样可以减少多个 Agent 同时处理同一任务的情况。

最后控制 Token 成本。系统为每个任务设置 Token 预算，也为每个 Agent 设置配额。预算或配额超限时，触发熔断并降级。共享上下文时，提取公共摘要。不要让每个 Agent 都携带完整背景。这样才能同时限制单个任务和单个 Agent 的消耗。

## 面试官会怎么追问

- **「你怎么判断一次委派是不是循环？」**  
系统记录任务的派发链路，并保留已经处理过的节点。相同任务再次回到这些节点时，就判定为循环风险并告警。委派深度达到上限时，也要停止继续向下派发。

- **「如果两个 Agent 同时拿到同一个任务，怎么避免重复执行？」**  
系统把任务和结果统一登记。Agent 认领前先查询登记表，确认任务是否已经被处理，或者结果是否已经存在。登记动作要作为认领前的检查依据，不能只依赖 Agent 自己判断。

- **「Token 预算和上下文摘要应该怎么配合？」**  
先给任务设置总 Token 预算，再给每个 Agent 设置自己的配额。超过任一限制时，触发熔断并降级。上下文传递时抽取公共摘要，避免每个 Agent 重复携带完整背景。

## 回答的坑

- 只设置委派深度上限，却不记录派发链路，仍然无法识别任务回到已处理节点的循环。
- 只限制总 Token 预算，却不给单个 Agent 设置配额，也不压缩共享上下文，成本仍可能快速上升。
