## 先这样答

从 0 开始搭建蚂蚁的 Agent 平台，我会分四步推进。第一步先做底层模型网关，统一接入多种模型，提供模型路由、限流和审计能力。这样上层 Agent 不需要直接依赖某一个模型，平台也能统一管理模型调用。

第二步建设工具层。平台需要支持插件协议，统一描述和调用外部工具。同时加入权限控制和沙箱，限制 Agent 能调用什么工具，以及工具运行时能访问什么资源。第三步建设编排层，提供 Agent 框架、记忆和评测能力。框架负责组织模型、工具和任务流程，记忆支撑连续交互，评测用来检查 Agent 的实际表现。

第四步再做开放。平台需要支持多租户，建设开发者生态，并提供计费能力。我会先选择内部场景验证平台，再逐步对外开放。安全和审计要从第一天放进架构，而不是等平台开放后再补。

## 面试官会怎么追问

- **「为什么不先做一个 Agent，再逐步补平台能力？」** 先做单个 Agent 能验证场景，但模型接入、工具权限和调用审计容易分散在业务代码里。先建设底层、工具层和编排层，可以让后续场景复用同一套平台能力。平台仍然要用内部场景验证，避免脱离实际需求。

- **「模型网关最先要解决什么问题？」** 先统一多模型接入，让上层调用不绑定某一个模型。再提供模型路由和限流，管理不同请求的模型选择与调用压力。所有调用都要留下审计记录，方便后续管理和检查。

- **「为什么安全和审计要从第一天做？」** Agent 会调用工具，也可能处理不同租户的请求。权限和沙箱如果后补，早期接口和数据边界可能已经固化。把安全与审计放进底层和工具层，后续开放时才有统一的约束和记录。

## 回答的坑

- 只讲模型和 Agent 框架，不讲模型网关、工具权限、沙箱以及审计，答案会缺少平台视角。
- 一上来就对外开放，跳过内部场景验证，也没有说明安全与审计的建设时点。
