## 先这样答

第一步是分级，不是上工具。把要发给模型的内容分三类：公开或低敏的直发；含个人标识（姓名、手机号、证件号、住址）的处理后再发；高敏数据（健康、金融、精确位置）原则上不出内网，走私有化部署或本地小模型。分级标准要业务和法务一起定，写进流程，不能靠开发者临场判断。

第二步是脱敏技术。主力是假名化：把真实标识替换成占位符（用户 A、`[[PHONE_1]]`），映射表留在内网，模型返回后再还原——模型全程没见过真实数据，业务流程无损。需要模型理解格式的场景（校验手机号位数之类）用格式保留的变换。比脱敏更省的是最小化：任务用不到的字段直接不发，很多场景把订单备注、联系方式整段砍掉就够用。第三步是输出回扫：模型可能在回答里复述敏感信息，出站前再扫一道，识别规则和输入侧共用一套。

流程动作别漏：给第三方 API 传用户数据要过法务评估、数据处理协议、隐私政策披露，必要时取得用户授权。技术和流程少一半都不完整。

## 面试官会怎么追问

- **「假名化会伤模型效果吗？」** 有影响但可控：跨指代理解、多主体一致性这类任务会变差一点，远好于把真实数据送出去。对效果确实敏感的场景，答案是私有化部署，而不是降低脱敏标准。
- **「识别规则怎么维护？」** 字段清单加内容识别双管齐下：结构化字段按清单处理，自由文本里的姓名手机号靠正则加 NER 模型识别；新字段上线先过评审，定期拿真实样本回扫验证规则覆盖率。
- **「厂商承诺不拿数据训练，能放心吗？」** 把承诺落成合同条款：数据处理协议、留存期限、区域限定、审计权利。高风险数据不依赖厂商承诺，直接私有化。

## 回答的坑

- 只处理输入不回扫输出。模型在回答里复述用户的敏感信息，是常见泄漏路径，出站扫描和入站脱敏是一对。
- 只做「删字段」。结构化字段好删，自由文本里藏的姓名、电话删字段拦不住，必须有内容识别这一层。
