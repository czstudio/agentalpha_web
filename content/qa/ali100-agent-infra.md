## 先这样答

Agent Infra 和 Agent 应用开发的区别，在于服务对象和要解决的问题不同。应用开发面向一个具体业务，做出一条 Agent 链路。它主要关心提示词怎么写、工具怎么接，以及最终效果是否符合业务要求。目标是把这条链路做好，让 Agent 能完成这个业务里的任务。

Agent Infra 面向平台，为所有 Agent 提供公共底座。它要处理沙箱与执行环境，也要提供上下文与记忆服务、工具注册与网关、评测与回放、观测与成本治理。这些能力不会只服务一个 Agent，而是让不同业务都能使用。类比 web 时代，应用开发像业务开发，Infra 更像应用平台。面试时可以把差别收束成一句话：应用解决一条链路的效果，Infra 解决规模化生产的问题。前者看单个业务能不能做好，后者看平台能不能支撑所有 Agent。

## 面试官会怎么追问

- **「如果只做一个 Agent，为什么还需要 Infra？」** 即使只看一个 Agent，也会用到执行环境、上下文与记忆、工具接入、评测和观测等公共能力。应用开发可以直接使用这些能力，不需要负责把它们做成面向所有 Agent 的平台。Infra 的边界不是某条业务链路，而是公共底座。

- **「Agent Infra 具体要负责哪些部分？」** 核心包括沙箱与执行环境、上下文与记忆服务、工具注册与网关、评测与回放、观测与成本治理。这些能力服务所有 Agent。回答时要说明它们属于公共底座，不要把它们讲成某个业务 Agent 的提示词或工具配置。

- **「你怎么判断一个问题属于应用开发，还是 Infra？」** 先看问题是否只围绕一个具体业务的一条 Agent 链路。如果重点是提示词、工具和效果，属于应用开发。如果重点是让所有 Agent 都能使用执行、记忆、工具、评测或观测等公共能力，属于 Infra。

## 回答的坑

- 不要把 Infra 说成把多个 Agent 链路简单拼在一起，它的重点是面向平台提供公共底座。
- 只背模块名（沙箱、记忆、工具、评测），答不出每个模块解决哪类生产事故；对照维度应该是：应用开发交付一条链路的效果，Infra 保障几百条链路的规模化生产。
