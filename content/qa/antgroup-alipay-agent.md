## 先这样答

支付宝上的 Agent 应该同时具备查询、办理和陪伴三类能力，并把准确、确认、合规、可追溯放在能力前面。它不能只会聊天，还要在金融场景里知道自己能做什么，什么时候必须停下确认，什么时候只能如实回答查不到。

查询类能力服务于账单、理财和出行票务编排。Agent 要先识别用户意图，再调用对应信息完成查询或编排。结果缺失时直接说明查不到，不能凭空补全。金融信息关系用户决策，准确率要求极高，少答也不能编。

办理类能力覆盖缴费和转账。Agent 执行写操作前，要让用户做强确认，并完成合规校验。每次写操作都要幂等，过程和结果都要可追溯，避免重复执行，也方便回看。陪伴类能力可以提供理财建议，但必须带免责说明，并做适当性判断。建议不能伪装成确定结论，也不能绕过用户确认和合规边界。这样答，既给出能力清单，也把支付宝金融场景的边界讲清楚。

## 面试官会怎么追问

- **「如果 Agent 要执行转账，你会怎么设计？」** 转账属于办理类能力，执行前必须让用户做强确认。系统还要完成合规校验，并保证写操作幂等。操作过程和结果都要可追溯，避免重复转账，也便于后续核对。

- **「查询结果不完整时，你会让 Agent 怎么回答？」** Agent 应该直接说明查不到，不要根据上下文猜测结果。金融场景的准确率要求极高，少回答也不能编造。它可以明确当前没有查到信息，但不能把不确定内容说成事实。

- **「理财建议和普通查询有什么区别？」** 理财建议属于陪伴类能力，不只是把信息展示给用户。Agent 提供建议时要有免责说明，并进行适当性判断。它不能把建议包装成确定结论，也不能忽略用户的实际适配边界。

## 回答的坑

- 只讲查询、缴费和转账，不讲强确认、合规校验、幂等和可追溯，答案就缺少金融场景的边界。

- 把理财建议说成确定答案，或为了完整而补写查不到的信息，都会直接触碰准确性和适当性要求。
