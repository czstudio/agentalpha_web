## 先这样答

这是一道常见的字节真题。开发人员按任务耦合度与规模决定多 Agent 的架构选型。系统开发默认从单 Agent 起步。开发人员把简单任务拆分成多 Agent 纯属自找麻烦。开发人员在系统遇到运行瓶颈后再考虑拆分架构。

Supervisor-Worker 架构适合处理可并行拆分的子任务。主管 Agent 负责把大任务分派给不同的工作 Agent。工作 Agent 接收任务后各自独立执行。主管 Agent 最后汇总所有工作 Agent 的执行结果。层级式架构适合大规模组织。任务规模变大导致系统内的 Agent 数量增多。层级式架构通过分组管理控制整体的通信复杂度。

去中心化多 Agent 架构适合没有天然中心决策的场景。多个 Agent 之间完全通过平等协商完成任务。这种架构的执行一致性较差。开发人员排查问题时的调试成本非常高。

## 面试官会怎么追问

- **「为什么不直接使用多 Agent 架构？」**
开发人员把简单任务拆分成多 Agent 纯属自找麻烦。多 Agent 架构会增加系统的通信复杂度。系统开发默认从单 Agent 起步。开发人员在系统遇到运行瓶颈后再考虑拆分架构。

- **「Supervisor-Worker 和层级式架构有什么区别？」**
Supervisor-Worker 架构适合处理可并行拆分的子任务。主管 Agent 负责分派子任务并汇总最终结果。层级式架构适合大规模组织。层级式架构通过分组管理控制整体的通信复杂度。

- **「什么场景适合使用去中心化架构？」**
去中心化架构适合没有天然中心决策的场景。多个 Agent 之间完全通过平等协商完成任务。这种机制导致任务执行的一致性较差。开发人员在排查问题时的调试成本非常高。

## 回答的坑

- 面试者盲目推崇去中心化架构并忽视其一致性差和调试成本高的缺点。
- 面试者忽略任务耦合度与规模并在简单任务中强行使用多 Agent 架构。
