# 你这个 Agent 是问答型、决策型还是执行型？边界是什么？

## 先这样答

我按输出对象给 Agent 定型：输出信息是问答型，输出选择是决策型，改变外部状态是执行型。这是百度真题里的三型分法。回答时，我先给自己的项目定型。我会说明项目最终交付什么，不只说它用了 RAG 或调用了工具。分类看输出对象，不看技术名称。

问答型给人看的答案，典型例子是 RAG 问答。它的边界是提供信息。决策型给系统的判断，比如风控判定、路由分派。它的边界是输出选择。执行型给外部世界的动作，比如下单、发消息、改配置。它的边界是改变外部状态。给出下单建议与实际下单，不属于同一种输出。

这三类的工程风险依次升高。我会把项目的输出和边界一起说清楚：只回答问题，还是给出判断，还是实际执行动作。项目如果属于执行型，我必须说明权限、幂等和审计配套。权限约束能做什么，幂等约束重复执行，审计记录执行动作。我的回答顺序是先定型，再讲边界，最后讲配套。

## 面试官会怎么追问

- **「你用了 RAG，为什么不一定是问答型？」** RAG 问答是问答型的例子，但我仍然看项目最终输出什么。只给人答案，就按问答型回答。输出风控判断或路由选择，就按决策型回答；实际下单、发消息或改配置，就按执行型回答。

- **「给用户一个下单建议，和替用户下单，边界在哪？」** 下单建议给人信息，没有实际下单，属于问答型。替用户下单改变外部状态，属于执行型。我会明确项目停在建议，还是已经执行动作。

- **「你说自己是执行型，那工程上多了什么要求？」** 执行型会改变外部状态，风险比问答型和决策型更高。我必须配权限、幂等和审计。回答不能停在“能执行”，还要说明这三项配套。

## 回答的坑

- 只报 RAG、工具调用等技术名称，却不说明输出对象，面试官仍然无法判断项目类型。
- 把输出选择和执行动作混为一谈，或者只说能执行却不讲权限、幂等、审计，都没有交代清楚边界。
