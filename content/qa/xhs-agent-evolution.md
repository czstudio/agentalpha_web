## 先这样答

Agent 架构通常经历三代演进：v1 是 Prompt 驱动，v2 是工具调用加 RAG，v3 是多智能体加动态 Context。每一代都在扩大模型能够处理的范围，也在增加架构对协作和状态的管理能力。

v1 主要依靠单次 LLM 调用和提示词工程。模型根据 Prompt 生成结果，系统本身没有接入外部能力。v2 通过 Function Calling 连接外部工具，同时加入知识检索。模型可以调用外部能力，也可以从检索结果中获得知识。这个阶段的重点是让模型不只依赖当前输入。

v3 引入多智能体和动态 Context。多个智能体可以分工协同，系统还需要管理任务状态，并根据过程自适应地组织上下文。面试时，我会继续对照自己的项目说明当前处于哪一代。我要讲清楚项目为什么属于这一代，以及下一代还需要补什么，而不是只背出三个阶段的名称。

## 面试官会怎么追问

- **「你的项目为什么属于 v2，而不是 v1？」**  
如果项目只有一次 LLM 调用和 Prompt，就属于 v1。项目接入了 Function Calling，能够使用外部能力，并通过知识检索获取信息，才可以归到 v2。判断标准看架构是否增加了工具调用和 RAG。

- **「v2 和 v3 的核心区别是什么？」**  
v2 关注模型如何连接外部能力，以及如何获得检索知识。v3 在此基础上加入多个智能体的协同，还要处理任务状态和动态 Context。核心区别不只是工具数量增加，而是系统开始管理协作过程和上下文变化。

- **「如果继续演进，你的下一步会补什么？」**  
我会先看项目当前缺少哪一层能力。如果现在处于 v1，下一步补 Function Calling 和知识检索。如果已经处于 v2，下一步重点补多智能体协同、状态管理和自适应 Context。选择下一步时，要结合项目当前的问题说明原因。

## 回答的坑

- 只按版本背名称，却不说明自己的项目处于哪一代，以及判断依据是什么。
- 把接入多个工具直接说成 v3，却漏掉多智能体协同、状态管理和动态 Context。
