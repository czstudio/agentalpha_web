## 是什么

MCP 采用三层结构。宿主应用内嵌客户端，与服务端建立会话。服务端暴露三类原语：可调用能力的工具、可读数据的资源和提示模板。传输层支持本地子进程通信（stdio）以适配本地工具，以及针对远程服务、支持流式返回的 Streamable HTTP 方式。

MCP 与函数调用定位不同。函数调用是模型输出意图的能力，MCP 则是应用与工具间的集成协议，服务端暴露的工具最终仍以工具调用形式交给模型处理。

协议本身不内置鉴权、授权与审计。接入第三方服务端存在提示注入与数据外泄风险，安全需由宿主应用与部署层负责。

## 解决什么问题

缺乏统一协议时，应用与工具的集成面临多对多的困境。每个应用接入新工具都需单独编写适配代码，开发成本随数量呈乘数级增长。

MCP 将这种乘法关系转为加法关系，实现了工具发现、调用和传输格式的标准化。工具方只需编写一次服务端，所有支持该协议的应用均可直接接入。

## 面试怎么考

常考 MCP 的概念与调用流程，需回答三层结构及三类原语的交互。高频考点是 MCP 与函数调用的区别，答题需明确函数调用是模型侧能力，MCP 是应用层集成协议。

工程实现上，常问 stdio 与 Streamable HTTP 的选型，需点明本地与远程的差异。考官也会问安全隐患，需指出协议无内置鉴权且有提示注入风险。有时要求口述手写服务端的步骤。
