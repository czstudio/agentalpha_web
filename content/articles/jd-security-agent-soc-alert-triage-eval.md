研判 Agent 的评测成绩单上，accuracy 是最没用的一个数。真实告警越稀有，漏报越不会暴露在总分里，全判误报照样能考高分。误报的代价是工时，漏报的代价是事故，两边分开计价，阈值才有地方落。

**👔 面试官：**简历上写你做过告警研判 Agent，上线半年把人工复核的告警量砍了一半，不错啊。那漏报涨了多少？

**🙋‍♂️ 我：**整体 F1 是提升的，漏的那几个 case 后来用规则兜底补上了。

**👔 面试官：**F1 把误报和漏报等权相加。你们 SOC 老板也这么大方？一条真入侵被自动化关掉，值一万条误报？

**🙋‍♂️ 我：**……那我们会单独盯高危规则的召回。

**👔 面试官：**我问的是评测。你们评测集多少条，真告警和误报的比例是多少，标签谁给的？

**🙋‍♂️ 我：**三百多条，标签是当年分析师的关单结论。

**👔 面试官：**分析师的关单结论？他当年一天处理四百条告警，手快一点就关错了，你把他的错误当 ground truth 又考了一年。上线这半年，你从生产里捞过 Agent 自动关掉的单去复查吗？

**🙋‍♂️ 我：**……出过事之后才看过几条。

**👔 面试官：**出了事才看，看的就是事故报告了，不叫评测。最后一个问题，上个月你们换了个新模型，评测数字要不要重跑？

**🙋‍♂️ 我：**……没跑，直接灰度上了。

这段对话里没有一句在问模型。面试官从头到尾在问研判 Agent 的评测体系怎么建、误报和漏报这笔账怎么算。题目数据、标签来源、代价不对称、换模型回归，一问一个坑。下面逐层拆。

01

QUICK ANSWER

### 💡 简要回答

这题我现在的做法是三步。第一步，把误报和漏报拆开报。研判是低基率二分类，行业报告里企业告警四成以上都是误报，早期 IDS 甚至九成以上是误报，这种分布下 accuracy 没有任何信息量，评测集必须分开报 escalate 精确率和 actionable 召回率两个数，各自算账。

第二步，给两个错误分别定价。误报的价签不是线性的，有对照实验把分析师分成误报率 50% 和 86% 两组，86% 那组判断精确率中位数从 0.80 掉到 0.33，处理同样的告警慢了 40%，人并没有变得更警觉；漏报的价签是事故期望损失，一次就能把半年误报省下的工时全部赔进去。第三步，用价格定工作点。不做单一阈值的自动研判，改成置信度路由，高置信才允许自动关单或自动升级，拿不准的进人工队列，自动化的收益按覆盖的那部分算，人工兜底的比例单独监控。

评测集本身也有讲究，标签要分析师复核加事后案件回补双来源，按生产基率配比，换模型、改 prompt 一律重跑回归，因为不同模型偏的方向差别很大，模型一换，工作点自己就漂了。

  

02

DEEP DIVE

### 📝 详细解析

accuracy 在这种题里是障眼法

先看一组真实的实验数字。Concordia 大学安全研究中心与加拿大国防科研机构的团队今年 3 月联合放出一个评测基准，叫 SIABench，专门测 LLM 做安全事件分析和告警研判。他们的告警分类实验里有一个极端不均衡的测试集，CIC-IDS2017 子集，5 条真实告警配 30 条误报。GPT-4o-mini 在这个集合上跑完，30 条误报只认出 14 条，总分 51.4%。这个数有多难看？你写一行代码把全部告警判成误报，什么都不用模型，准确率就有 85.7%。它连「全判误报」这个笨蛋基线都没跑赢。

问题的根源在分布。真实攻击在网络流量里本来就是稀有事件，安全学界二十多年前就给它起了名字，Axelsson 2000 年那篇著名的分析管这叫基率谬误，攻击占流量的比例低到分类器再准也扛不住误报淹没。后来引用最广的一个口径是 Julisch 2003 年总结的，IDS 告警九成以上是误报，极端情况 99%。分布偏到这个程度，单看 accuracy 就是在给一个永远说「没事」的考生打分。

SIABench 的另一个测试集（TII-SRC-23，50 真 50 假）把这事看得更清楚。同一个集合上，GPT-5 判真告警对 48 条、判误报全对，总分 98%；Claude-4.5-Sonnet 反过来，50 条真告警一条不漏，误报漏了 4 条，总分 96%。两个模型分数只差 2 个点，偏的方向完全不同，一个敢关单、一个不敢关单。你按哪个总分去选型，取决于你缺的是分析师工时还是怕漏一条入侵。

「在 5 真 30 假的集合上，什么都不判、全说误报，也有 85.7% 的准确率。」

![](/images/articles/jd-security-agent-soc-alert-triage-eval/fig02.jpg)

— 误报漏报分开计价，置信度阈值决定两边各流过去多少

误报涨回来，人不只是变慢，是会漏

有反对意见说，多几个误报怎么了，分析师加加班就消化了。消化不了的，有实验为证。UNC Wilmington 的 Layman 和 Roden 做过一个对照实验，把参与者按 IDS 误报率分组，一组 50%，一组 86%，后一组接近真实系统的水平，任务就是从告警堆里把真攻击挑出来。结果 86% 组的判断精确率中位数从 0.80 掉到 0.33，干同样的活慢 40%。灵敏度这一项没有显著差异，人被淹没之后并没有变得更小心，只是更不准、更慢。

![](/images/articles/jd-security-agent-soc-alert-triage-eval/fig03.png)

图：误报率对分析师判断精确率的影响（50% 与 86% 误报率两组的精确率箱线图，86% 组中位数从 0.80 掉到 0.33）

误报的成本不能按线性算，这个实验就是证据。你把 Agent 调保守，误报重新涌回人工队列，省下的复核工时拿不回来，人在淹没状态下的判断质量自己会掉。还有一个工程上更疼的，信任塌方。分析师一旦发现自动化关掉的单里混着漏报，就会重新全量人肉复查，你上一版压下去的误报量等于白干。CORTEX 那篇多智能体研判的工作也提到，行业报告估计企业告警里四成到四成五是误报，SOC 每天要处理几万条告警，其中只有一小部分指向真实威胁，这是所有研判系统共同的处境。

所以这笔账要分开记。误报率决定自动化省下的工时和人的判断质量，漏报率决定事故期望损失和系统信任。两个都涨的调参方向不存在，评测要为这个取舍服务，别拿一个合成分数去汇报。

「人被误报淹没之后，不会变得更小心，只会更不准、更慢。」

阈值、路由、兜底，把工作点明着定下来

既然分数不能合成一个，工程上怎么办？把「自动」和「人工」的边界做成显式机制。CrowdStrike 的研究团队今年 7 月放出一篇工作，在真实人工标注的 Windows 端点检出数据上训练会写推理链的研判分类器，整体测试准确率 82.6%。更关键的设计在后半段，系统里单独训了一个校准器，读完推理链后估计这条研判结论正确的概率，只有高置信的部分才允许进入自动化关单。在这个高置信工作点上，benign 召回比直接打标签的基线高 43 个百分点，malicious 召回高 18.3 个百分点。论文里还有个反直觉的消融，把没训练过的置信度裁判直接拿来用，高置信段的召回直接归零。置信度要单独训练，模型不会白送。

升级侧的兜底逻辑可以用结构写死。CORTEX 是 George Mason 大学和 Fluency Security 合作做的多智能体研判架构，行为分析 Agent 把告警路由进不同工作流，证据收集 Agent 去外部系统查证，推理 Agent 汇总，最后用一个「任何一路证据可疑就升级」的保守规则出结论。在它那个评测上，单智能体工具调用基线的 actionable F1 是 0.66，误报率 24.9%，CORTEX 做到 F1 0.78、误报率 14.2%，代价是更多的协调开销，仍然压在每张工单 3 分钟的处置时限内。方向很清楚，用结构换召回，用路由换精确，两个数同时改善的路径存在，但每一条都要拿评测数字说话。

图：CORTEX 的四阶段研判流水线（告警经编排、行为分析、按工作流收集证据、推理协调四个阶段，输出升级或四类不升级判定，任一路升级即整体升级）

「自动化率，由你划下的那条置信度线决定。」

![](/images/articles/jd-security-agent-soc-alert-triage-eval/fig05.jpg)

— 分数好看，是因为漏的不算分

评测集自己才是最大的考点

模型和机制都有论文可抄，评测集抄不走，面试官的追问一般落在这里。四个要点。

标签双来源。分析师的关单结论只能当草稿，要抽样人工复核定标；另一路从事后案件回补，把当年真实入侵工单里被误关的告警捞回来，专门补漏报侧的样本。上一篇工具授权那篇里说的回滚演练，在评测里对应的就是漏报考古。

配比按生产基率。评测集里真假告警的比例要接近你们 SOC 真实流量，不要为了凑平衡集把基率改得面目全非，改完之后精确率召回率全失真。TII-SRC-23 那种 50 比 50 的集子适合做能力上限测试，做上线验收就得换回生产分布。

![](/images/articles/jd-security-agent-soc-alert-triage-eval/fig06.png)

图：SIABench 的告警样本构建流水线（从攻击与 benign 流量段生成 pcap 工件，配场景、工具、问题与 ground truth，标签经过构建流程而非直接抄关单结论）

动态换血。SIABench 团队在实验设计里专门安排了 live 任务，用模型知识截止之后新发布的靶场题去测，为的就是排掉数据污染。你的告警样本进了模型训练语料或者被 prompt 调参反复白嫖之后，分数就开始虚高，评测集要按季度轮换、留盲盒。

换模型必回归。回到开头那个坑，为什么不同模型偏的方向差那么多，因为阈值行为、指令跟随、长度偏好都变了，模型一换等于工作点自己漂移。改 prompt、换模型、加工具，评测全量重跑，这个数字就是发布门禁，这和上篇讲授权层「当攻击面测」是同一层纪律。

![](/images/articles/jd-security-agent-soc-alert-triage-eval/fig07.png)

图：SIABench 的模型一致性分析（各模型在不同任务类别与难度下的准确率分布，难度上升后模型间差距和方差同步放大，分数不能外推）

面试现场还会追问的三件事

这类题大概率还有追问，提前备好。第一问，能不能用 LLM 当裁判直接给研判质量打分？可以打分，但别让它当 ground truth，裁判自己也会被告警文本里藏的注入带偏，位置偏差那套去偏手段是裁判层的，不是标签层的。第二问，自动化率定多少合适？没有标准答案，看误报侧人工队列的消化能力和漏报侧审计的抽样比例，先把复查机制立起来，再逐步扩大自动化覆盖面，SIABench 的端到端实验也提醒过激进的理由，最强的模型在他们的完整事件分析任务上，25 个场景也只有 8 个全对，「全自动研判」这个说法目前在实验室里都不成立。第三问，攻击者知道你的评测机制怎么办？研判 Agent 读的是攻击者亲手写的告警文本，评测集除了防分数虚高，还要防被针对性投喂，盲盒样本和不进任何语料的保留集是底线。

SUMMARY

### 🎯 面试总结

回到开头那段对话，三个典型误区。

第一个误区，拿 accuracy 或单一 F1 汇报。基率偏到九一开的任务里，总分是最容易骗人的数字，两个方向的错误必须分开报、分开定价。第二个误区，把分析师的历史关单结论直接当 ground truth，标签自己就是被淹没状态下产生的，错误会被评测集固化。第三个误区，以为调保守或者调激进有一劳永逸的答案，工作点是价格和容量决定的，人工队列消化能力、审计抽样比例变了，阈值就得重定。

把「误报漏报拆开计价、置信度路由定工作点、评测集双标签加生产基率加动态换血、换模型必回归」这四件事讲清楚，再把 SIABench、CORTEX、Layman 的对照实验、CrowdStrike 的校准器这几个按方法和团队名字带出来，这道题就稳了。

阶段 9｜Agentic RL（1–1.5 周）

**学什么：**把「搜索/工具调用」建模成 RL 环境中的动作；交错推理加多轮搜索的训练流程；奖励函数设计与 PPO、GRPO、Reinforce 的选型对比；训练稳定性技巧（retrieved token masking、防止模型走捷径、动态采样与难度过滤、训练数据配比）；veRL、EasyR1、Search-R1 三个框架的技术路线与递进关系。

**动手做什么：**复现 Search-R1，训练一个 3B–7B 的小模型，让它在「思考→触发搜索→整合→回答」的结构里学会何时发起搜索。

**怎么验收：**报告必须包含训练前后模型检索次数与搜索触发位置分布的变化、答案质量（F1/EM）与「引用有效率」的提升、以及 1 到 2 个失败样本的归因和改进思路，比如把评测集换成生产基率配比、给自动关单加上百条抽样复查时，检查误报和漏报两个数是分开汇报的，还是又被合成了一个总分。

**学员案例**（来自社区公开资料）：字节 Seed、腾讯、京东 TGT、蚂蚁 PLAN-A、华为天才少年等录用结果；ICLR、KDD、ICML、NeurIPS、EMNLP、AAAI 等论文录用；USC、杜克、港科大等博士录取。
