# 货拉拉业务Agent评测平台的工程实践与深度思考

大模型时代，业务 Agent 正在客服、调度、用户司机协作这些核心业务场景里铺开。从「Demo 演示惊艳」到「敢放进生产环境」，中间隔着一整套质量评测与工程保障体系。这篇拆货拉拉技术团队公开的《货拉拉业务 Agent 评测平台的工程实践与深度思考》，把工业界怎么让 Agent 质量从「不可知、不可控」变成「可量化、可验证、可卡点」的完整做法过一遍：五大分层架构、六大工程支柱、三代评测范式，以及平台跑出来的真实数据。

## 一、为什么业务 Agent 评测这么难

### 1.1 一个让人尴尬的交付现场

团队耗时一个月，基于工作流或自研 LLM 做出一个「智能客服/调度助手」Agent。Demo 演示时表现很出彩：意图识别精准、工具调用行云流水、多轮对话滴水不漏。

一到生产环境，问题接踵而至：

•**回答漂移**：同一个费用解答场景，昨天按标准口径回答，今天版本微调后直接给用户承诺了优惠券；

•**工具误调/死循环**：遇到复合查询，Agent 反复调用同一个接口拉数据，直到 Token 耗尽超时；

•**非确定性输出**：测试环境 100% 通过的用例，线上遇到微小的 Prompt 扰动或多轮上下文累积，直接答非所问；

•**性能崩塌**：高并发下首字延迟（TTFT）从 800ms 飙到 5s+，流式输出频频中断。

更棘手的是排查日志时的感受：每一次模型调用的单步推理看起来都合理，最终的业务交付结果就是错的。没有统一基准的时候，研发改一处 Prompt，往往修好一个 Bug，顺带引入三个新缺陷。

图 1 ｜ 网上真实漫画：改完代码运行成功，但说不清为什么（《神秘的程序员们》）

### 1.2 核心症结：传统测试与单点打分的双重失效

传统测试和单点 Prompt 评估撑不起业务 Agent，原因在以下三重失控：

![传统接口测试 vs 业务 Agent 评测](/images/articles/huolala-agent-eval-platform/fig02.png)

图 2 ｜ 传统接口测试与业务 Agent 评测的差异（图片来源：货拉拉技术公众号原文）

1**确定性断言失效**：LLM 的输出是概率性的，传统的 equals 或正则断言判断不了「一段语义表述准不准确、有没有幻觉、有没有踩业务红线」。

2**上下文与工具链路复杂**：业务 Agent 不是「一问一答」，而是多轮迭代的动态决策链路。从用户提出目标开始，Agent 要依次完成意图理解、计划生成、步骤选择、工具调用、结果处理，再根据中间结果判断要不要修正规划或重试，循环到交付最终结果。链路里深度集成了企业 MCP 工具库、知识库检索、工作流调用。错误可能发生在「意图理解 - 参数提取 - 工具选择 - 结果组装 - 规划修正」的任意节点，而且问题有传导性：上游的理解偏差会被下游工具调用逐级放大。

3**性能度量维度跃迁**：Agent 场景的性能不再只是 QPS。首字生成时间（TTFT）、总生成时间（TTLT）、Token 吞吐速率（TPS）直接决定真实用户的交互体验。

![Agent 执行链路](/images/articles/huolala-agent-eval-platform/fig03.png)

图 3 ｜ Agent 的多轮迭代执行链路（图片来源：货拉拉技术公众号原文）

**Agent 能跑，不代表能用；单次回答惊艳，不代表生产稳定可靠。** 业务 Agent 的生产级交付，需要一套完备、客观、自动化的评测基础设施来支撑。

## 二、评测范式演进：从「凭感觉点测」到「工业化流水线」

货拉拉业务 Agent 评测体系的建设经历了三个阶段：

| 演进阶段 | 核心特征 | 评测手段 | 痛点与局限 |
| --- | --- | --- | --- |
| 第一代：人工盲测与单点 Prompt 打分 | 靠工程师人工单句提问，肉眼比对效果 | 少量 Excel 用例，单轮输入输出校验 | 覆盖度极低、主观性强、无法自动化回归 |
| 第二代：离线数据集与单一 LLM-as-a-Judge | 引入离线 Benchmark 数据集与大模型裁判打分 | 离线批处理脚本、单一相似度算法 | 裁判模型有幻觉与自评偏见、脱离发布流水线、缺性能度量 |
| 第三代：全生命周期自动化评测平台 | 业务规则 + 智能裁判 + 拦截隔离 + CI/CD 门禁 + 性能压测 + 线上巡检 | 多元协议打通、动态流水线卡点、多维基准度量 | Agent 质量可量化、可验证、可卡点、可持续迭代 |

| 支柱五：大模型性能与稳定性压测 | 怎么评估 Agent 在高并发与流式交互下的极限表现 | 自研 LLM 压测引擎；支持固定/阶梯/线性爬坡曲线；精确度量 TTFT、TTLT、RPS 及 Token 吞吐 |
| 支柱六：CI/CD 门禁、追踪与缺陷归因 | 怎么无缝嵌入交付流水线，做长会话还原与低分缺陷归因 | 支持准入（Admit）与准出（Exit）评测，分数不达标自动熔断发布；低分专项筛选与专家人工复核 |

## 四、核心支柱的工程落地与技术细节

### 4.1 支柱一：全方位智能体资产治理与链路拓扑

![评测实验室结构](/images/articles/huolala-agent-eval-platform/fig05.png)

图 5 ｜ AgentNameSpace 评测实验室与智能体注册结构（图片来源：货拉拉技术公众号原文）

不同业务线（客服、货运助手）对 Agent 的要求不一样。平台通过评测实验室做多租户隔离，并建立统一的 Agent 元数据模型：

•**命名空间与项目隔离**：按项目空间和业务线做多租户资源隔离；

•**多平台纳管**：对接内部自研工作流/模型平台及自定义 Agent HTTP 服务；

•**版本与环境追踪**：关联 Agent 的代码版本、Prompt 版本、知识库切片和运行环境（PRE/PRD），保证每次评测结果都可复现；

•**流式交互与协议解析**：原生支持非流式与 SSE 流式响应，用 resultPath（JSONPath）与 resultType（Path / Shell）对多模态异构结果做精准提取。

参数动态映射与拦截器上，平台设计了三类切点拦截器：

•**三级切入点**：TASK\_BEFORE（任务执行前）、SESSION\_BEFORE（多轮会话前）、REQUEST\_BEFORE（单次请求前）；

•**切点类型与变量注入**：支持 AGENT\_CASE（用例数据集动态注入）与 SHELL\_REF（脚本动态引用），把计算产物强类型映射成 String、Number、Boolean、JSONObject 或 JSONArray，注入 Agent 请求报文。

针对 Agent 输出的非标准嵌套 JSON、Markdown 混杂或特殊格式，平台提供 AgentConfig 规则引擎：

•**嵌套 JSON 快速点选**：页面调试 JSON 返回结果时，支持点选提取 response 字段与通用字段映射；

•**内置 Groovy 脚本执行**：支持在沙箱里动态运行清洗逻辑，把复杂输出结构化成标准评测载荷。

调用链拓扑与标签体系上：定义源 Agent 与下游目标 Agent 的调用关系，支持 ANY / ALL 复合匹配规则；在智能体维度建立「业务域、能力项、风险等级、用例类别」多维标签，按标签动态下发用例集与调用链路由。

### 4.2 支柱二：数据集测试数据合规校验与准入门禁

「垃圾数据输入，只会产生垃圾评测结果」。测试数据集未严格校验就下发，容易出两类问题：

1**数据污染与环境越界**：误用线上未脱敏的生产数据或非测试环境标识，Agent 调用工具时可能触发非预期的真实写操作；

2**算力与 Token 浪费**：用例格式错误（必填字段缺失、JSON 语法不合法、参数类型不匹配），Agent 跑几十轮对话后底层报错崩溃，白白消耗大量推理 Token。

平台为此构建了基于测试数据校验规则引擎的前置准入卡点：

![数据准入校验流程](/images/articles/huolala-agent-eval-platform/fig06.png)

图 6 ｜ 前置数据准入校验引擎流程（图片来源：货拉拉技术公众号原文）

•**多维动态数据校验规则引擎**：面向不同业务实验室与智能体场景，按需沉淀细粒度的测试数据契约规则。强制校验请求参数里是否包含合法的测试环境标识，严禁未脱敏的线上真实数据或非测试账号混入评测集；深度检查 Headers、Params、Body 是否符合目标 Agent 入参 Schema，包括必填字段完整性、字段类型、取值枚举范围和 JSON 格式合法性。

•**发起前批量预检与秒级阻断**：流水线准入/准出触发或用户点击「发起评测」的同一时刻，系统调用 checkAgentInfoAndCases 对所选数据集做全量扫描。发现哪怕 1 条用例不合规，直接阻断评测调度，不生成评测 Job；同时返回校验诊断报告，明确是哪一条用例、哪个字段违反哪项规则，引导用例维护者在前端修正。

### 4.3 支柱三：多模复合智能裁判与多维评分体系

单一的大模型裁判（LLM-as-a-Judge）有三类问题：裁判自身概率波动（打分漂移）、缺乏分层业务约束（打分规则一刀切）、多轮对话孤立评判（割裂整体体验）。对订单号、金额、JSON 数据结构这类强确定性事实，只靠 LLM 判读容易漏检误判。

平台的做法是「内置五大确定性规则 + 三维 Prompt 组合裁判 + 裁判引擎抗波动 + Session 级红线穿透」：

![多模复合裁判体系](/images/articles/huolala-agent-eval-platform/fig07.png)

图 7 ｜ 多模复合智能裁判体系（图片来源：货拉拉技术公众号原文）

**五大内置确定性规则引擎（硬约束打分）**，由计算型引擎直接执行，毫秒级、零幻觉：

•**结构化校验**：校验 Agent 输出 JSON / XML 的格式合法性、字段完整性、Key-Value 数据类型及嵌套 Schema 契约，适用于 Tool Calling 入参生成与结构化报表场景；

•**正则匹配**：用预置或自定义正则校验订单号、手机号、车牌号、金额、日期等关键业务实体的提取准确率；

•**硬匹配**：对标准枚举值、固定系统指令、特定操作返回码做字面全等判定；

•**关键词匹配**：支持「必须包含词」「禁止违规词」和命中词频阈值，用于服务禁言、红线合规与关键话术覆盖度校验；

•**语义相似度**：基于文本嵌入向量计算 Agent 回答与标准参考答案（Golden Reference）的余弦相似度，判定大段非结构化文本的语义贴近度。

**三维 Prompt 模板动态组合体系**，分层注入：

•**平台级模板**：沉淀全局通用评测元规则，包括 0~100 分制打分尺度、事实性与幻觉判定准则、结构化打分理由与扣分点输出格式；

•**Agent 维度模板**：注入具体业务 Agent 的角色定位、业务边界与专业规范（客服话术风格、运力调度决策口径、赔付承诺权限等）；

•**用例维度模板**：绑定单条测试用例的特定上下文、意图判定要点（Rubric）、期望提取参数和特定业务场景的判定逻辑。

三层模板解耦维护，打分时按需组装，避免每个用例都重复写冗长背景。

**裁判引擎抗波动机制**：

•**并发多次采样**：对单条评测产出，并发下发多路独立裁判请求（支持相同或异构 Judge 模型）；

•**离群过滤与均值聚合**：剔除偏离度过大的异常极值打分，对有效置信区间内的打分做加权均值聚合；

•**方差监控与置信度熔断**：多次采样方差超过阈值，判定该样本存在打分争议，自动推入人工复核池。

**Session 级多轮综合评分：短板与红线穿透原则**。多轮对话里孤立地对每一轮 Query-Response 单点打分再平均，会掩盖关键阶段的业务崩溃（比如前 9 轮服务正常，第 10 轮突然向用户泄露商业底价或给出违规承诺）。平台在会话级度量里引入端到端综合评分：

•**红线与短板穿透**：任意一轮触发超级红线违规（违规承诺、敏感数据泄露、越权写操作）或核心步骤严重错误，该单项扣分直接穿透到整个 Session 的全局总分（一票否决或封顶惩罚）；

•**渐进加权平均分**：多轮对话越长，上下文腐烂和意图漂移的概率越高，系统采用前轻后重的渐进权重曲线，越靠后的轮次权重越高，考验 Agent 在长程交互里的持久记忆与逻辑韧性。

**客观评测与主观评测并行：人工校准 + 自动沉淀**：

![客观评测与主观评测对比](/images/articles/huolala-agent-eval-platform/fig08.png)

图 8 ｜ 客观评测与主观评测的定位与分工（图片来源：货拉拉技术公众号原文）

•**客观评测**覆盖高频、结构化、可规则化的部分，由确定性规则引擎执行，守住质量底线，全量、毫秒级自动化校验；

•**主观评测**覆盖开放性、高价值、复杂业务场景，由多模复合智能裁判执行，拉升体验上限；

•**人工复核校准 + 自动沉淀**：争议用例、红线触发样本或重点业务版本，业务专家通过可视化复核工作台人工打分与标注；人工修正的样本自动沉淀为黄金对齐数据集，反哺迭代裁判 Prompt 与评分规则，让评分规则随人工修正持续更新。

### 4.4 支柱四：体系化评测计划与全景报告聚合

把评测能力嵌进 CI/CD 流水线，是拦住「带缺陷上线」的核心防线：

![评测计划与报告聚合](/images/articles/huolala-agent-eval-platform/fig09.png)

图 9 ｜ 评测计划与全景报告聚合流程（图片来源：货拉拉技术公众号原文）

•**评测计划与版本对比基准**：支持针对不同业务能力项设定目标分与权重，自动计算加权达标情况；关联业务需求与缺陷统计，让评测计划成为研发与业务协同的共同语言；显式关联当前版本与对比基线版本，直观度量 Prompt 迭代、模型升级前后的分数波动。

•**功能 + 性能 + 安全一体化全景报告**：把智能体元数据、响应配置、功能评测明细、性能压测数据与安全表现整合成一站式评测画像；评测结束自动生成报告，支持一键推送到指定飞书群组。

### 4.5 支柱五：大模型性能与稳定性压测引擎

针对业务大模型在长文本、流式输出、高并发场景下的性能瓶颈，平台内置自研 LLM 性能压测引擎：

![LLM 压测引擎](/images/articles/huolala-agent-eval-platform/fig10.png)

图 10 ｜ LLM 异步压测引擎（图片来源：货拉拉技术公众号原文）

•**多元压力曲线**：支持固定并发、线性爬坡，模拟业务早晚高峰流量；

•**流式精准计时**：针对 SSE 流式响应，精确捕捉首 Token 到达时间（TTFT）与完整文本生成时间（TTLT）；

•**压测指标大盘**：响应耗时（RT）、首字延迟（TTFT）、吞吐量（RPS）、完整耗时（TTLT）和请求失败率，用于容量规划与模型选型。

评测要落到交付流程里才起作用。平台通过嵌入交付流水线、提供排查工作台，保障 Agent 长期运行质量：

•**CI/CD 流水线准入准出门禁**：准入评测在合并代码或变更 Prompt 时自动触发核心冒烟用例集；准出评测在发布前执行全量基准测试，自动比对目标分数（purposeScore），分数不达标流水线直接返回 FAIL 并阻断发布。

•**低分专项筛选与缺陷处理**：低分雷达支持按分数阈值快速拉取低分用例列表，聚焦缺陷；业务专家可在工作台对争议结果二次复核与改分，修正样本沉淀为裁判模型的优化数据；线上分钟级自动巡检生产环境 Agent，发现异常即时告警。

### 5.2 缺陷拦截：从「上线救火」到「前置防线」

平台前置拦截的缺陷覆盖智能体执行过程的六类问题：

| 问题大类 | 典型场景 | 占比 |
| --- | --- | --- |
| 意图与指令理解 | 意图识别错误、指令忽略/漂移、语义理解偏差 | 33.84% |
| 智能体与工具执行 | 工具调用幻觉、执行死循环、状态记忆不同步 | 31.12% |
| 回答准确性 | 事实性幻觉、检索漏召回、逻辑推理断层 | 25.38% |
| 性能与响应体验 | 首 Token 超时、全量超时、输出抖动 | 5.44% |
| 格式与输出规范 | 格式规约破坏、生成重复死循环、流式解析报错 | 2.72% |
| 安全合规 | 提示词注入/越狱、敏感信息泄露、过度拒答 | 0.91% |
| 其他 | 误操作、重复提交 | 0.59% |

核心结论：意图理解与工具执行两类问题合计约 65%，是 Agent 质量问题的大头——这正是传统「单点打分式评测」最容易漏掉的部分，因为传统评测只看最终答案对不对，不关心中间链路是否正确。

### 5.3 业务实战：AI 邀约的效能变化

以 AI 邀约业务为例，接入评测平台后在需求吞吐量翻倍（+80%）的背景下，线上质量与研发效能同步改善：

| 核心指标 | 灰度前 | 灰度后 | 变化 |
| --- | --- | --- | --- |
| 月均需求吞吐 | 2.2 个 | 4.0 个 | 需求量 +80%，支撑业务迭代节奏加快 |
| 月均发布次数 | 33 次 | 14 次 | 单次发布质量提升，发布次数下降 57% |
| 月均质检 Badcase | 439 个 | 351 个 | 上线质量提升，线上体验改善（减少 20%） |
| 算法投入人力 | \- | 释放 41.5 人天/月 | 降本提效 |

在交付效率提速、线上质量守住的条件下，业务指标没有因为加评测而下降——质量平台的价值不是拖慢迭代，而是让快迭代少翻车。

### 5.4 全场景覆盖：从高频回归到深度探隐患

平台已打通自研工作流平台、大模型、自定义 Agent 协议等多元异构入口，以功能、性能、安全及自动化流水线等多维评测能力，覆盖公司不同类型的智能体场景。从使用模式看有两类典型范式：

•**高频防退化型**（代表：AI 促增长）：迭代频繁、回归量大，平台承担高强度自动回归，确保核心主流程稳定不退化；

•**深度探隐患型**（代表：降外投 / AI 邀约）：场景复杂、工具链深，平台靠丰富的场景用例和多模裁判能力，挖掘复杂工具调用里的隐蔽异常。

头部 3 个重点项目（AI 促增长、降外投、AI 邀约）贡献了近 85% 的评测量，拦截了 60% 的核心质量缺陷——平台既能扛住海量高频回归的吞吐压力，也具备针对复杂 Agent 的深度探测能力。

## 六、未来演进

业务 Agent 评测还在快速演进。货拉拉技术团队列了三个方向：

1**从「静态用例」走向「Agent 对抗评测（Agent-vs-Agent Evals）」**：借鉴对抗生成思想，由专门的「红队进攻 Agent」动态生成刁钻、对抗性的边缘用例与多轮对话陷阱，持续对业务 Agent 做自动化压力对抗。

2**多 Agent 协同系统（Multi-Agent System）链路评测**：当业务架构从单 Agent 变成「协调者 + 多个专业子 Agent」，评测重点从单体输出质量扩展到 Agent 间通信效率、协作死锁检测、任务分解合理性及全局状态一致性。

3**评测驱动的自适应优化（Eval-Driven Auto-Tuning）**：把评测结果直接接到 Prompt 自动调优器与模型微调数据飞轮上，评测分数低于阈值时自动提炼失败样本、优化 Prompt/Few-shot，实现自我迭代。

## 结语

对业务 Agent 的生产交付来说，评测不是上线前的一道手续，而是一套持续运行的工程系统。货拉拉这套实践的可参考点在于：确定性规则守硬事实，智能裁判管开放语义，数据校验拦脏输入，门禁熔断卡发布，压测与巡检盯线上——每一环都有明确的执行位置和判断标准，Agent 质量因此从「凭感觉」变成「看数据」。这对正在自建评测体系、或者面试被问到「Agent 评测怎么做」的人，都是可以直接对照的工程样本。
