研判 Agent 依赖的那套私有知识，不是灌进向量库就能一劳永逸。漏洞今天补了、检测规则这周改了、内部处置手册上个月更新了，可检索只认词面像不像，不认文档新不新。旧结论就排在新证据前面被捞出来，Agent 一本正经地报一个早就修掉的漏洞。

**👔 面试官：**简历写你在安全团队做过研判 Agent 的知识库，把上千条内部处置手册、检测规则和漏洞情报喂给 RAG，也就是检索增强生成，效果不错。那我问个运营半年之后的事，你怎么知道它现在给你的结论还是对的？

**🙋‍♂️ 我：**知识库是每周全量重建一次索引的，新文档会进库。

**👔 面试官：**进了库，就等于被用上了？上个月刚发补丁的一个高危 CVE，也就是公开漏洞编号，你库里那条分析结论还是三个月前判「误报可忽略」的版本。向量检索按相似度召回，旧文档写得比新文档还详细，词面更像，它排在前面，你的 Agent 读哪条？

**🙋‍♂️ 我：**……一般会先命中排在前面的那条。

**👔 面试官：**那就是拿旧结论压新证据。你别急着重建索引，先告诉我，你有没有单独一个指标，专门测「库里有更新版本、模型却还在用旧答案」的比例？

**🙋‍♂️ 我：**没有，我们看的是整体问答准确率。

**👔 面试官：**整体准确率里，过期和不过期混在一起，你根本看不出是哪一类在烂。最后一个问题，有人提议干脆把新结论直接训回模型参数里，省得每次检索，你怎么看这个方案？

**🙋‍♂️ 我：**……参数更新我了解得不深，不敢说。

这段对话没有一句在问模型结构。面试官从第二句起就在问同一件事：私有知识的时效性怎么管，过期召回和旧结论压新证据这两个坑怎么填。下面逐层拆。
![](/images/articles/knowledge-freshness-jd-agent-mian-4shi/fig01.jpg)


📌 本文看点

01  旧文档比新文档更抢手
02  检索到新证据不等于会用
03  更新要放在检索层

### 💡 简要回答

这题我现在的做法分三层。第一层，承认私有知识自己会过期，检索要带时间维度。有个专门测过期信息的基准叫 HoH，往检索库里掺入同主题的新旧两版文档，发现不给召回加时间衰减时，过期文档进前 5 条的命中率反超了真正相关的文档，一旦掺进过期信息，主流模型至少掉两成。这说明向量检索默认偏向写得像而不是说得对，光靠语义相似度排不出新旧，必须显式引入时间戳做双路召回。第二层，检索到新证据不等于模型会用新证据。模型参数里存的旧知识和检索到的新文档会打架，FreshLLMs 那套评测显示模型在快速过期的问题上断网直答正确率很低，接上实时检索才大幅回升；专门研究知识冲突的工作也发现，模型在信检索到的上下文和信自己记忆之间摇摆，两个答案同时给对的比例只有约五成。所以检索之后要有一步显式的冲突消解，把新旧证据摆到一起比时间、比来源，而不是无脑取第一条。第三层，更新要落在检索层，不要指望改模型参数。把新事实一条条训回权重里的知识编辑方法，做到几十上百条就明显退化，还可能牵连别的知识。更稳的路子是给每条知识带版本和存活期，更新时把旧结论标记为失效而不是删除，保留一条什么时候被谁取代的痕迹，再用带时间戳的知识图谱去检索。这套东西最后必须落到一个单独的时效指标和一道人工门禁上，高危知识的更新不能静默覆盖。

### 📝 详细解析

私有知识不灌一次就完，过期是常态

先破除一个错觉，很多人把建知识库理解成一次性搬家，把漏洞情报、检测规则、处置手册一股脑灌进向量库，之后只做全量重建，从不问哪条已经作废。安全领域恰恰是知识贬值最快的地方。有一篇做漏洞分析的工作统计过，十年里公开漏洞库里二十多万个条目，超过三万个后来被更改或者更新过。也就是说研判 Agent 参数和知识库里存下的旧结论，有相当一部分随时在和新证据冲突，过期的东西会把结论实打实带错。

这里有个反直觉的工程事实，过期文档往往比新文档更容易被检索命中。原因很朴素，旧文档通常写得更完整、更长、示例更多，词面信息和查询的重叠度反而更高。HoH 这个基准把同一主题的新旧版本都放进库里测召回，不给时间任何权重时，过期内容进前 5 条的命中率是 0.8837，真正该用的相关文档只有 0.8707，旧的排到了新的前面。要治这个，得从检索本身下手，给它补一条时间轴。

「检索只认词面像不像，不认文档新不新，旧结论天然占便宜。」
![](/images/articles/knowledge-freshness-jd-agent-mian-4shi/fig04.png)

— HoH 基准的动机示例：问现任美国总统，检索却命中旧条目，给出过期答案


给检索加一条时间轴，让新证据能赢过旧文档

怎么把时间放进检索。最轻的做法是每个文本块入库时带上它对应事实的生效和失效时间，召回时除了按语义相似度排序，再叠一层按「这条现在还成立吗」的过滤和加权，做语义、时间双路召回。LongMemEval 这个长时记忆基准做过对照，它专门有时间推理这一类题目，在检索查询里加一步按时间扩展的处理，这类题的召回能明显往上走几个点，其余题型不动。时间信息得进到检索这一步，光指望大模型自己从一堆相似文本里闻出哪条更新了，不稳。
![](/images/articles/knowledge-freshness-jd-agent-mian-4shi/fig02.jpg)

— 三层做法：入库带时间戳、召回走双路、更新有门禁


再往下是更新机制的设计。一条新结论要覆盖旧结论时，别把旧的直接删掉。删了就没有追溯，出事故复盘时你查不到 Agent 当时到底依据的是哪一版。更好的做法是旧的标记为失效、新的标记为生效，库里同时留着两版，检索默认只召回生效版本，复盘时能回放，一条知识什么时候被谁取代都留了痕。Zep 这套给 Agent 做记忆的时间知识图谱就是按这个思路设计的，它给每条关系挂上生效、失效时间，遇到冲突把旧的那条标成失效，而不是抹掉。


检索到新证据，不等于模型会用新证据

这是最容易被跳过的一层，也是面试官最想听的。你把更新后的文档放进库了，检索也确实把新文档捞上来了，模型回答时却仍然可能按参数里那点旧印象说事。这叫知识与记忆冲突。研究这类冲突的一篇 COLM 工作给了组很直白的对照。当检索到的上下文和模型自己的记忆矛盾时，让模型按上下文的证据作答，正确率明显高于按它记忆里的答案作答。可麻烦在于两个答案同时给对的比例只有五成上下，模型经常在这两头之间摇摆，不会稳定地倒向新证据。

外部检索的时效收益也很实在。FreshLLMs 团队专门造了一批会快速过期的问题去测，模型关联网直接作答时，在今天的答案是什么这类快过期问题上正确率很低，GPT-4 也就在一成多附近，而且六成时候干脆拒答。一旦给它挂上搜索引擎做实时检索再喂回去，正确率大幅回升，涨了将近一半。这印证了前一句，新证据必须真被读到、被采信，光躺在库里不算数。

更麻烦的是多文档之间也互相矛盾。MAGIC 这个基准专门测冲突检测，它造了需要多跳推理、且检索回来的文档彼此打架的场景。跨模型平均下来，MAGIC 上能把冲突检出来的分数只有约六成，定位到具体哪一段的分数只有约三成六，在三个同类基准里最低，比另外两个既有基准明显掉一档。多一跳，检出的和定位的分数还要再往下掉。开源闭源模型都一样吃力。所以检索之后要有一步显式的冲突消解，把候选证据连同时间戳和来源一起交给模型，让它先判断这几条里谁更新、谁更可信，再作答，别默认排第一的就是对的。

「放进库不等于检索到，检索到不等于用得上，中间每一步都在漏。」
![](/images/articles/knowledge-freshness-jd-agent-mian-4shi/fig03.jpg)

— 补丁都发了三天了，它还拿上个月的结论糊弄我？


想靠改参数覆盖旧知识，这条路撑不住

有人会说，既然检索到上下文模型还可能不用，那干脆把新结论直接训回模型权重里，让参数记忆本身就是最新的，不就一步到位。这条路在研究里叫知识编辑，代表性方法像 ROME、MEMIT。听起来优雅，实测撑不住规模。一篇出自中科院自动化所的工作指出，ROME、MEMIT 这类方法在持续编辑几十到上百条之后就会出现明显退化，编辑后的模型没法再用，作者把原因归结为知识叠加，新知识没真学进去、只是盖在旧知识上层，互相干扰。安全领域动辄几万条要更新的漏洞结论，靠一条条编辑权重既不现实，还会把本来对的也带偏。

所以结论很清楚，时效这件事不要放进权重层解决，放进检索层解决。权重负责通用能力，知识库负责「此刻什么是真的」。这也解释了前面为什么要带版本、带时间戳、带失效标记，本质是把「更新」变成一个数据层动作，可控、可回滚、可审计，而不是一个训练层动作。


更新要有自己的指标和门禁，别静默覆盖

机制讲完，落回面试官那句「你有没有单独一个指标测过期」。多数团队的现状是没有，只有整体问答准确率。问题是整体分把过期和不过期搅在一锅，掉分了你也定位不到是哪一类知识在烂。LongMemEval 的实测提醒过这个风险，长会话里一旦需要跨会话、跨时间调用记忆，模型准确率会掉三到六成，把全部历史一股脑塞进上下文，也远不如精准取到该取的那几条。时效必须有单独口径。

具体到安全 Agent，我会单独盯三个数。第一个是知识更新成功率，看库里某条事实换了新版之后，Agent 是否改口用新版。第二个是过期召回率，看检索返回的片段里已经失效的版本占了多大比例。第三个是冲突解决率，看新旧证据同时被召回时模型选了哪一边。这三个数分开报，不进那个合成分，跟上一篇讲告警研判把误报和漏报拆开计价是同一套纪律。

更新动作本身要有门禁。低危知识可以自动生效，比如一条普通资产的端口清单变了。高危知识必须人工确认再覆盖，比如某检测规则从误报改成真告警，这种翻转一旦被模型悄悄学了去，代价可能是漏掉一次真实入侵。所以走审核、留版本、可回滚。下一篇专门写这套东西怎么变成发布门禁，golden set、金丝雀、回滚指标三件套，改 prompt、换模型、更新知识谁先跑谁后跑。

「高危知识的更新方向如果是误报改真告警，就不该允许它静默生效。」

### 🎯 面试总结

回头看开头那段对话，三个典型误区。

第一个误区，把建知识库当一次性搬家，之后只做全量重建，从不给文档标生失效，过期是常态却被当成意外。第二个误区，以为更新版进了库、被检索捞到，模型就会用新的，忽略了参数里的旧知识和新证据会打架，中间还差一步显式的冲突消解。第三个误区，想靠把新结论一条条训回模型参数来解决时效，这条路在几十上百条规模就退化，还不留追溯。

把「检索加时间轴做双路召回、旧结论标失效不删除、检索后做冲突消解、更新走检索层加时效指标加人工门禁」这四件事讲清楚，再把 HoH、FreshLLMs、Zep、LongMemEval、MAGIC 这几个按团队或方法名字带出来，这道题就稳了。

下一篇把这套时效纪律推到发布门禁，聊 golden set、金丝雀、回滚指标三件套怎么定改 prompt、换模型、更新知识的先后。

挑一个和今天最相关的模块，看看具体教什么、动手做什么、怎么验收：

阶段 9｜Agentic RL（1–1.5 周）

**学什么：**把「搜索/工具调用」建模成 RL 环境中的动作；交错推理加多轮搜索的训练流程；奖励函数设计与 PPO、GRPO、Reinforce 的选型对比；训练稳定性技巧（retrieved token masking、防止模型走捷径、动态采样与难度过滤、训练数据配比）；veRL、EasyR1、Search-R1 三个框架的技术路线与递进关系。

**动手做什么：**复现 Search-R1，训练一个 3B–7B 的小模型，让它在「思考→触发搜索→整合→回答」的结构里学会何时发起搜索。

**怎么验收：**报告必须包含训练前后模型检索次数与搜索触发位置分布的变化、答案质量（F1/EM）与「引用有效率」的提升、以及 1 到 2 个失败样本的归因和改进思路，比如知识更新后，检查 Agent 是不是改口用了新版结论、过期召回有没有被单独盯住。

**学员案例**（来自社区公开资料）：字节 Seed、腾讯、京东 TGT、蚂蚁 PLAN-A、华为天才少年等录用结果；ICLR、KDD、ICML、NeurIPS、EMNLP、AAAI 等论文录用；USC、杜克、港科大等博士录取。
