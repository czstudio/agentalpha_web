# 基模越能干，安全数据越不能缺

模型开始写代码、读文件、调用工具，security 的分量就变了。

一段有漏洞的代码，可能被直接部署。

一个异常文件，可能被交给工具执行。

网页里夹带的恶意指令，也可能影响智能体下一步操作。

模型的回答，开始变成系统里的实际动作。

所以我觉得，做基模的团队，现在就该把安全能力放进训练和评测计划。

这里说的 security，指网络与软件安全：模型能不能看懂程序的危险行为，判断输入是否可信，发现漏洞并验证修复。

这些能力和代码理解、复杂推理、工具使用直接相关。基模能理解哪些机制，会影响后训练能教会它什么，也会影响下游应用需要补多少防护。

当然，实际部署还需要权限控制、沙箱和审计。模型自身的安全判断，也值得单独训练、单独测。

## 一个直观的案例：执行目标混淆

拿我们最近整理的 20 个 Windows 漏洞来说，有一类现象特别直观：

用户点的是 A，软件实际执行了 B。

这叫"执行目标混淆"。看起来是一次普通的打开操作，背后却涉及程序启动接口的回退处理。

![执行目标混淆现场录屏：用户以为在执行备份操作，实际弹出了计算器（演示素材）](/images/cases/dm-exec-confusion-01.jpg)

## 做成评测任务，安全能力就能验收

如果做成评测任务，可以给模型操作记录和程序行为证据，看它能不能找出目标变化的位置、解释触发条件，再验证修复有没有影响正常功能。

对采购团队来说，这样的任务能把"安全能力"变成可以验收的结果：原因找对了吗？证据够不够？有没有误报？修复是否有效？

这也是我们做 cyber 数据想深入的方向。
